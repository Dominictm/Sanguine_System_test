## Краткое резюме

Патч затрагивает пять несвязанных областей UI/логики Sanguine System:

1. **Нити** — навигация от «Висящих нитей» на Панели к конкретной нити на странице Нити (скролл + подсветка).
2. **Броски** — FAB-роллер `dice.js` (решение Q-B1): работа без выбранного персонажа, скрытие нулевых способностей + вариант «Не владеет» (+2 к сложности однократно), бросок добродетелей и Силы воли.
3. **Сессия** (экран живой игры `page-session`) — условное скрытие навигации по сценам, карточки модулей вместо `<select>`, sticky-панель справа, новый блок «Заметка сцены» с сохранением в **отдельный файл `scene_notes.md`**, «Заметки сессии» **секцией в `<mod>.md`**, перепривязка кнопки записи сессии к форме записи страницы модуля (префилл агрегатом заметок сыгранных сцен).
4. **Связи** — убрать zoom-кнопки (оставить только иконку «Сброс» с tooltip), добавить фильтр по типам связи чекбоксами.
5. **Лист персонажа** — переименование кнопки `+`, tooltips, кумулятивные чекбоксы временной Воли/Крови, перенос/лейбл/центрирование блоков состояния, перестановка Человечность/Путь, вкладка «Фамильяр» (через связь в «Отношениях»).

Все открытые вопросы закрыты решениями пользователя — см. раздел «Принятые решения».

**Ключевые файлы:** `web/public/scripts/scripts.js` (Панель/навигация), `web/public/scripts/archive.js` (страница Нити), `web/public/scripts/dice.js` (FAB-роллер — единственное окно броска в патче), `web/public/scripts/session-screen.js` (экран сессии), `web/public/scripts/modules.js` (страница модуля, запись сессии), `web/public/scripts/graph.js` (Связи), `web/public/scripts/char-detail.js` (модалка персонажа), `web/public/index.html`, `web/public/styles.css`. ## Фаза 1 — Нити (Панель → страница Нити)

### Требование
При выборе нити из «Висящих нитей» на Панели — не просто открывать страницу Нити, а проскроллить/подсветить конкретную выбранную нить.

### Задача 1.1 — Передавать id+file нити при навигации из дашборда
**Текущее поведение.** Блок «Висящие нити» рендерится в `scripts.js:280-289` (`renderDashboard`). Каждая строка — `<button class="dash-stale-row stat-clickable" data-nav="threads" ...>` — содержит только `data-nav="threads"`, без идентификатора нити. Клик обрабатывается делегированным `data-nav` (см. `scripts.js:453`: `if (card) { navigate(card.dataset.nav); return; }`) → просто `navigate('threads')`.

Нити в API имеют `t.id` (номер строки в файле) и `t.file` (город-относительный путь), см. `web/routes/threads.js:33-37` и рендер карточек `archive.js:40`: `<div class="thread-card ..." data-id="${t.id}" data-file="${escHtml(t.file || '')}">`. **Важно:** `t.id` уникален только внутри файла — разные файлы (`archive/open_threads.md`, `chronicles/*/open_threads.md`) нумеруются с 1 независимо, поэтому для точного матча нужна пара `id`+`file`.

**Предлагаемое изменение.**
- В `renderDashboard` добавить на строку `data-thread-id="${t.id}"` и `data-thread-file="${escAttr(t.file || '')}"` (данные уже есть в объекте `t`).
- В делегированном обработчике клика (район `scripts.js:453`) при наличии `data-thread-id` вызвать `navigate('threads')`, затем передать целевую нить в загрузчик — например через модульную переменную `_pendingThreadFocus = { id, file }` (объявить в `archive.js`) или через параметр в `loadThreads`.

**Файлы:** `web/public/scripts/scripts.js`.
**Критерий готовности:** клик по строке «Висящих нитей» переходит на страницу Нити И сохраняет намерение сфокусироваться на конкретной нити.

### Задача 1.2 — Скролл и подсветка целевой нити на странице Нити
**Текущее поведение.** `loadThreads()` (`archive.js:18`) перерисовывает список карточек `.thread-card[data-id][data-file]`. Скролла/подсветки к конкретной карточке нет. `navigate('threads')` вызывает `loadThreads()` (`scripts.js:194`).

**Предлагаемое изменение.**
- В конце `loadThreads()` (после установки `innerHTML`) проверить `_pendingThreadFocus`; если задан — найти `.thread-card[data-id="…"][data-file="…"]`, вызвать `el.scrollIntoView({ behavior:'smooth', block:'center' })` и добавить CSS-класс подсветки (напр. `thread-card--focus`) с авто-снятием через `setTimeout` (~2 c) или по `animationend`. Сбросить `_pendingThreadFocus = null`.
- Учесть асинхронность: `navigate('threads')` запускает `loadThreads()` (async, fetch). Фокус выполнять внутри `loadThreads` после рендера, а не сразу после `navigate()`.
- Добавить в `styles.css` класс подсветки: временное свечение/рамка через существующие переменные (`--accent`, `--gold` и т.п.), без литеральных hex. Анимация — плавная, уважать `prefers-reduced-motion` (по возможности).

**Файлы:** `web/public/scripts/archive.js`, `web/public/styles.css`.
**Критерий готовности:** переход из дашборда прокручивает список к нужной нити и кратко подсвечивает её; повторный обычный переход на «Нити» (без выбора нити) фокус не выполняет.
**Тест:** source-guard в `all.test.js` — проверить, что `scripts.js` содержит `data-thread-id`, а `archive.js` содержит `scrollIntoView` и класс подсветки.

## Фаза 2 — Доработка броска V20

> **Решение (Q-B1 принято):** ВСЯ доработка броска делается в глобальном **FAB-роллере** `web/public/scripts/dice.js` (`#dice-fab`/`#dice-panel`), у которого уже есть селект персонажа (`#dice-char-sel`) и выпадающие «Атрибут»/«Способность». Модалку броска из листа `v20-sheet.js` (`_v20OpenRollModal`, `#v20-roll-modal-backdrop`, `v20-sheet.js:565-681`) в этом патче НЕ трогаем. Все задачи фазы ниже относятся к `dice.js` (+ при необходимости справочник имён из `rules-v20.js`). Ссылки на `v20-sheet.js` оставлены только как контекст, правки туда не вносятся.

### Задача 2.1 — Бросок без выбранного персонажа
**Текущее поведение.**
- FAB (`dice.js`): при пустом `#dice-char-sel` `_diceFillFromModel(null)` (`dice.js:99, 60-66`) **отключает** оба селекта (`attrSel.disabled = abilSel.disabled = true`) и оставляет только placeholder-опции. То есть без персонажа выбрать атрибут/способность нельзя, пул задаётся вручную числом.
- Модалка листа (`v20-sheet.js`): опции строятся из `_v20Model` (`_v20RollOptionsHtml`, `v20-sheet.js:592-599`) — окно вообще открывается только из листа.

**Предлагаемое изменение (решения Q-B2/B3 приняты).**
- Ввести статический справочник ВСЕХ атрибутов и способностей V20 (имена + группы) — источник: `V20_ATTRS` (используется в `dice.js:68`), `V20_ABILITIES`/аналог из `rules-v20.js`. При пустом `#dice-char-sel` заполнять оба селекта полным списком (все атрибуты и все способности), НЕ отключать их (сейчас `dice.js:99, 60-66` их `disabled`).
- **Семантика пула без персонажа (Q-B2):** значения точек неизвестны, поэтому пользователь задаёт числовые значения вручную. Практичный вариант: рядом с каждым селектом (или через уже существующее поле `#dice-pool`) пользователь вводит значения выбранного атрибута/способности, из которых собирается пул. База сложности — **6** (дефолт `#dice-diff`). Конкретный способ ввода значений вручную описать при реализации (мини-инпуты значений vs общий `#dice-pool`); поведение с выбранным персонажем (значения из листа) не меняется.

**Файлы:** `web/public/scripts/dice.js`, возможно `rules-v20.js` (справочник имён атрибутов/способностей).
**Критерий готовности:** без выбранного персонажа выпадающие списки показывают все атрибуты и все способности; пул собирается из введённых вручную значений; база сложности 6.

### Задача 2.2 — Скрытие нулевых способностей + вариант «Не владеет» (+2 к сложности)
**Текущее поведение.**
- FAB (`dice.js:71-78`): в `abils` попадают все слоты с `slot.name` независимо от значения; опции — `${label} (${val})`, включая `(0)`.
- Модалка (`v20-sheet.js:596-597`): аналогично — способности с `s.name` добавляются с любым `val`, включая 0.
- Сложность считается пользователем вручную (поле `#dice-diff` / `#v20-roll-diff`), варианта «Не владеет» нет.

**Предлагаемое изменение (решение Q-B3 принято).**
- При построении опций **способностей** (`_diceFillFromModel`, `dice.js:71-78`) фильтровать `val > 0` — нулевые способности не показывать. Атрибуты по тому же правилу `val>0` (это корректно уберёт единственный штатный ноль-атрибут — Внешность Носферату).
- Добавить в выпадающий список способностей пункт **«Не владеет»** (спец-value, напр. `unskilled`). При его выборе: способность даёт **0** кубиков, а к сложности **+2 ровно один раз**.
- **Однократность +2 (Q-B3):** сложность вычислять от БАЗОВОЙ (пользовательской) сложности, а не инкрементом поля. Хранить базовую сложность отдельно (напр. `diffEl.dataset.base` или переменная), а эффективную считать как `base + (unskilled ? 2 : 0)`. Так повторное переключение «Не владеет» ↔ реальная способность НЕ накапливает +2 (при снятии «Не владеет» возвращается база). Пример из ТЗ: Ловкость 4 + Вождение 2 → сложн. 6; Ловкость 4 + «Не владеет» → сложн. 8; переключение туда-обратно → снова 6/8, без 10/12.
- Точка расчёта: `_diceApplySheetPool` (`dice.js:114-118`) и обработчик броска `#dice-roll` (`dice.js:145-157`) — там, где формируется `pool` и `difficulty`. Чистая логика `rollV20Pool` (`dice.js:16-37`) не меняется — «Не владеет» влияет только на входные `pool`/`difficulty`.

**Файлы:** `web/public/scripts/dice.js`.
**Критерий готовности:** нулевые способности отсутствуют в списке; «Не владеет» даёт 0 кубиков от способности и +2 к эффективной сложности однократно (без накопления при повторных переключениях); пример из ТЗ воспроизводится.
**Тест:** unit-тест `rollV20Pool` не трогаем (логика не меняется); добавить source-guard, что в `dice.js` есть пункт «Не владеет» и расчёт от базовой сложности (`+2` не инкрементом).

### Задача 2.3 — Бросок добродетелей (+ Сила воли в списке)
**Текущее поведение.** Ни FAB, ни модалка не предлагают добродетели. Добродетели в модели листа — `m.virtues.{conscience, selfcontrol, courage}` (`v20-sheet.js:80, 1608-1610`), постоянная Воля — `m.willpower.permanent` (`v20-sheet.js:85`). Существуют per-row иконки броска на листе (`rollIcon`, `v20-sheet.js:1548`), но добродетели их не имеют.

**Предлагаемое изменение (в FAB-роллере `dice.js`).**
- Добавить в окно броска возможность бросить одну строку из группы «Добродетели»: Совесть/Решимость, Самоконтроль/Инстинкты, Смелость и **Сила воли** (постоянная) — Силу воли кладём в тот же список добродетелей, чтобы не плодить поля (требование ТЗ).
- Реализация: расширить модель листа, читаемую в `_diceFillFromModel` (`dice.js:59-80`), — сейчас она берёт только `m.attributes` и `m.abilities`; добавить чтение `m.virtues.{conscience,selfcontrol,courage}` и `m.willpower.permanent` (модель приходит из `_v20ModelFrom`, `dice.js:110`). Вывести отдельный селект/опцию-группу «Добродетель» со значениями точек. При выбранной добродетели пул = её значение (бросок добродетели/Воли идёт без второго слагаемого).
- Режим без персонажа (2.1): значения добродетелей неизвестны → пользователь задаёт вручную (как в 2.1).

**Файлы:** `web/public/scripts/dice.js`.
**Критерий готовности:** в FAB-окне броска можно выбрать добродетель или Силу воли и бросить их пул; поля не раздуваются (Сила воли — внутри списка добродетелей).
**Тест:** source-guard на наличие опций добродетелей/Силы воли в `dice.js`.

### Снятый риск (важно)
- **Затирание заметок сцен AI-регенерацией `scenario.md` — СНЯТО ПОЛНОСТЬЮ.** Так как «Заметки сцены» вынесены в отдельный файл `scene_notes.md` (решение Q-S1), они изолированы от AI-контента `scenario.md`. Прежняя задача «3.5b — защита `### Заметка *` при перезаписи scenario.md» из плана УДАЛЕНА как неактуальная; правок в `fill.js`/`scenario.js` под заметки не требуется. Заодно снят риск коллизий парсинга сцен/локаций/НПС с под-секциями заметок.

### Технические зависимости и заметки
- **Фаза 3 связки:** 3.2 (карточки модулей) меняет способ выбора модуля — 3.5/3.6/3.7 зависят от того, что модуль выбран. Порядок: 3.1 → 3.2 → 3.3 → 3.4 → (бэкенд 3.5/3.6) → UI 3.5/3.6 → 3.7.
- **Существующие тесты про `#sess-mod-sel`:** перед удалением select (3.2) проверить, что e2e/ui-тесты на него не завязаны (иначе адаптировать).
- **graph.js обработчики (4.1):** удаление кнопок в HTML без удаления `addEventListener` вызовет краш при загрузке (обращение к `null`) — правки обязательно парные.
- **Миграции:** новые файлы `scene_notes.md` и секция в `<mod>.md` создаются лениво по требованию — жёсткая миграция `tools/migrations/` НЕ нужна. Новая секция в `<mod>.md` должна быть безопасна для существующих регэкспов `list.js` (участники/метаданные — по своим заголовкам).

### Оставшаяся мелкая неоднозначность (не блокирует)
- **«Граница текущей сессии» для агрегата (Q-S3):** нет явного маркера начала сессии; принятый дефолт — «сцены с заметками, не покрытые прошлыми записями сессий». При реализации допустимо сузить диапазоном до текущей сцены включительно.
