# Данные для техспеки: пикер дисциплин из библиотеки (по образцу пикера титулов)

**Собрано:** Аналитик, 2026-08-08. **Передаётся:** Системному аналитику на техспеку.

**Задача пользователя** (дословно): «Реализовать в карточке персонажа выбор дисциплин на
подобии выбора титула из библиотеки. Добавить возможность добавления нескольких дисциплин из
библиотеки в строку Дисциплины в модальном окне персонажа».

---

## 0. Как читать этот документ

Задача — прямое продолжение пикера титулов (A2.8, 2026-08-07,
[`2026-08-06-char-loc-city-fields-techspec.md`](2026-08-06-char-loc-city-fields-techspec.md)
§2.8) для соседнего поля «Дисциплины» той же вкладки «Информация». Отличие от титула —
принципиальное: титул один, дисциплин может быть несколько, и текущее решение по ним уже
было принято явно (A3, §0.2 того же документа): «только автодополнение в существующем
текстовом поле, без переделки в чип-пикер». Эта задача **пересматривает то решение** —
пользователь, увидев готовый пикер титулов, хочет тот же паттерн и для дисциплин. Фиксирую
явно, не молчаливо: старое решение не «забыто», оно осознанно заменяется новым запросом.

---

## 1. Текущее состояние

### 1.1 Поле «Дисциплины» — только вампиры

`INFO_FIELDS_BY_LINEAGE.vampire` (`scripts.js:2013-2037`) — единственная линейка с полем
`disciplines`; у fairy/mortal/generic его нет вовсе (подтверждено QA 2026-08-08 живым
прогоном — карточка смертного в режиме редактирования не показывает это поле). Значит пикер
дисциплин, в отличие от пикера титулов (нужна была проверка `_lineageOf(...) !== 'fairy'`),
**не нуждается в проверке линейки** — ветка `key === 'disciplines'` в `_enterInfoEdit`
физически не может сработать ни для кого, кроме вампира.

### 1.2 Сегодняшний ввод — datalist, свободный текст, без структуры

`char-detail.js:1123-1130` (ветка `key === 'disciplines'` в `_enterInfoEdit`) — простой
`<input list="cdet-disciplines-list">`. Автодополнение построено на
`_cdetDisciplinesDatalistOptions(currentValue, clanName)` (`:1219-1228`) — токенизация по
запятой, клановые дисциплины сортируются первыми (через `v20ClanInfo(clanName).disciplines`),
уже добавленные — исключаются из списка подсказок. Пересборка — на `input`-событие поля
«Дисциплины» И поля «Клан» (`:1237-1244`).

**Реальные данные не структурированы.** Карточка персонажа хранит поле одной строкой
свободного текста, например (Ален Дюбуа, живые данные):
```
Dominate, Fortitude, Presence (клановые Вентру; предположительно)
```
Голые английские названия без перевода, вперемешку с примечанием в скобках — не список из
трёх токенов, а два токена + произвольный комментарий, приклеенный к третьему.

### 1.3 Библиотека дисциплин — другой формат имени

`GET /api/library/disciplines` (проверено живым прогоном, `web/lib/titles.js`-аналог для
дисциплин) — 21 запись, каждая как
```json
{ "name": "Анимализм (Animalism)", "clans": "общая (Гангрел, Носферату, Равнос)", "slug": "animalism", "group": "base", ... }
```
`d.name` — **русское название с английским в скобках**, не голое английское слово. Именно
это полное значение (`d.name` целиком) уже подставляет сегодняшний datalist
(`_cdetDisciplinesDatalistOptions`, `:1227`, `${prefix}${n}` где `n = d.name`).

**Следствие:** формат «Дисциплины» на существующих карточках (голый английский, как в
примере Алена) и формат, который льёт сегодняшний datalist / будет лить новый пикер
(«Русское (English)»), — разные. Это не новая проблема этой задачи (datalist уже так себя
ведёт с 2026-08-07, A3), но **касается детекции «эта дисциплина уже добавлена»** в новом
пикере напрямую — см. §3.3.

### 1.4 Пикер титулов — образец, на который явно ссылается пользователь

`char-detail.js:1131-1166` (разметка) + `:1246-1327` (логика, границы файла — сверено
2026-08-08). Ключевые элементы паттерна:
- Кнопка `📚` (`.cdet-lib-pick-btn`) рядом с полем, в обёртке `.cdet-field-with-pick`.
- Раскрывающаяся встроенная панель `.v20-lib-picker` (не модалка поверх модалки — design.md
  §1.2 исходной техспеки), toggle по кнопке.
- Поиск (`.v20-lib-search`, живой фильтр по `input`).
- Две группы: «По вашей секте/клану» (`priority`, скрывается при пустоте) / «Все титулы»
  (`all`, показывает «Ничего не найдено…» при пустом результате поиска — фикс QA 2026-08-08).
- Клик по `.v20-lib-item` → **подставляет значение в поле целиком** (перезаписывает),
  закрывает панель, фокус — назад в поле.

**Для дисциплин последний пункт — главное структурное отличие.** Титул — одно значение,
перезапись корректна. Дисциплины — список; клик должен **добавлять** элемент к текущему
значению поля, не заменять его, и панель не должна закрываться после одного клика — иначе
«добавить несколько» потребует открывать пикер заново на каждую дисциплину.

## 2. Что нужно (декомпозиция запроса)

1. Кнопка `📚` рядом с полем «Дисциплины» (тот же `.cdet-field-with-pick` + `.cdet-lib-pick-btn`
   паттерн, что уже есть у «Титул»).
2. Панель пикера, визуально идентичная титульной: поиск + две группы («Клановые» / «Все
   дисциплины» — по аналогии с «По вашей секте/клану» / «Все титулы», источник группировки —
   уже существующий `v20ClanInfo(clanName).disciplines`, тот же, которым сегодня сортирует
   datalist, п.1.2).
3. Клик по элементу списка — **добавляет** дисциплину к текущему значению поля (через запятую),
   не заменяет. Панель **остаётся открытой** после клика — можно добавить подряд несколько.
4. Уже добавленные дисциплины — видимо помечены в списке (иначе непонятно, что уже выбрано,
   особенно при повторном открытии панели).
5. Ручной ввод в поле остаётся рабочим всегда (как у титула) — пикер не блокирует и не
   подменяет прямой текстовый ввод, только ускоряет типовой случай.

## 3. Открытые технические развилки — решения Аналитика

### 3.1 Повторный клик по уже добавленной дисциплине — удаляет её (toggle)

**Решение:** да, toggle. Клик по элементу списка, который уже есть в поле, **убирает** его
оттуда (симметрично добавлению). Обоснование: пикер без возможности отмены выбора неполон —
если пользователь ошибся или передумал, единственный путь исправления без toggle — редактировать
текст поля руками, что обесценивает сам смысл «выбирать из списка, не набирать текст». Toggle —
стандартное поведение мультиселект-виджетов, ожидаемо пользователем без дополнительного
обучения. Значит каждый `.v20-lib-item` в этом пикере при повторном рендере списка должен
визуально отражать состояние «выбрано» (см. §3.4) — не просто список кнопок, а список
переключателей.

### 3.2 Datalist не убирается — пикер добавляется рядом

**Решение:** оставить существующий `<input list="cdet-disciplines-list">` как есть, кнопку
`📚` — добавить, не заменяя механизм. Обоснование: прямая аналогия с полем «Титул», где после
A2.8 сосуществуют и ручной ввод (с datalist-подсказкой — там её, впрочем, нет; для дисциплин
она уже есть отдельно от пикера), и кнопка-пикер. Убирать рабочий, уже протестированный
механизм автодополнения ради нового виджета — рост риска без выигрыша: два способа быстрого
ввода (набрать буквы → увидеть datalist-подсказку, или открыть панель → кликнуть) не мешают
друг другу, обслуживают разные привычки набора.

### 3.3 Детекция «уже добавлена» — сопоставление по значимой части имени, не по строгому равенству

**Проблема** (см. §1.3): на карточке — «Dominate», в библиотеке — «Доминирование (Dominate)».
Строгое сравнение токена поля с `d.name` не найдёт совпадение на существующих (легаси) данных
— пикер показал бы дисциплину как «не добавленную», хотя по факту она уже в списке текстом,
и повторный клик задвоил бы значение другой записью того же понятия на двух языках.

**Решение:** для каждого токена текущего значения поля (после сплита по запятой, до любого
хвостового примечания в скобках) проверять вхождение **английского имени** дисциплины
(извлечённого из `d.name` регэкспом `/\(([^)]+)\)/` — та же скобочная часть, что уже кладёт
библиотека) ИЛИ полного `d.name` ИЛИ **русской части** `d.name` (до скобки) — три варианта
совпадения, регистронезависимо, по подстроке (не точному равенству токена — токен на карточке
может содержать собственный хвостовой комментарий типа «Dominate 3» или «Dominate (предп.)»).
Это эвристика, не гарантия (свободный текст поля принципиально не формализуем полностью), но
покрывает и легаси-карточки (голый английский), и записи, добавленные новым пикером (полное
`d.name`).

### 3.4 Визуальная пометка «уже добавлено» — не просто фильтрация из списка

**Решение:** дисциплина, уже присутствующая в поле (по эвристике §3.3), **остаётся в списке**,
но помечается (например — класс-модификатор на `.v20-lib-item`, галочка ✓ перед именем вместо
скрытия). Не убирать из списка вовсе (как делает сегодня datalist — `_cdetDisciplinesDatalistOptions`
фильтрует `already` из выдачи, §1.2): если убрать, toggle-удаление (§3.1) станет невозможно —
кликнуть нечем, элемента для клика-удаления не будет в DOM.

### 3.5 Клановая группировка — переиспользовать источник, не переизобретать

**Решение:** группа «Клановые» строится из `v20ClanInfo(clanInput.value).disciplines` — той же
функции и того же поля «Клан», что уже сортирует datalist (`_cdetDisciplinesDatalistOptions`,
`:1222-1223`). Источник истины один, не два параллельных списка кланово-дисциплинных
соответствий. Группа скрывается при пустом клане — тот же паттерн, что «По вашей секте/клану»
у титула (`priorityGroup.style.display = priority.length ? '' : 'none'`).

### 3.6 Пересборка при смене «Клан» во время открытой панели

**Решение:** если пользователь меняет поле «Клан» при открытой панели пикера дисциплин — панель
перерисовывается (та же логика, что уже перестраивает `datalist` на `input`-событие поля «Клан»,
`:1237-1244`, только вместо `<option>`-списка теперь два `.v20-lib-list`-блока). Технически —
дописать существующий делегат `input`, не заводить второй.

## 4. Риск/сложность

| Аспект | Оценка | Комментарий |
|---|---|---|
| Разметка/кнопка/панель | низкий | прямое копирование паттерна титула, готовые CSS-классы `.v20-lib-picker`/`.v20-lib-list`/`.v20-lib-item`, только новый модификатор «уже выбрано» |
| Логика добавления (без закрытия панели) | низкий | одна ветка `if/else` вместо «подставить и закрыть» |
| Toggle-удаление | средний | требует парсинга текущего значения обратно в список токенов и пересборки строки — операция, которой не было ни у титула (нечего удалять из одного значения), ни у datalist (datalist ничего не «снимает», только предлагает) |
| Детекция «уже добавлено» на легаси-данных | средний | эвристика по §3.3, не 100%-надёжна на полностью произвольном тексте — задокументировать как best-effort, не гарантию |
| Клановая группировка | низкий | переиспользование существующего `v20ClanInfo` |
| Зависимости | нет новых | `ensureDisciplines()`/`_disciplinesCache` уже загружаются (A3, `_ensureCdetLibDatalists`) |

**Рекомендация Аналитика по объёму техспеки:** сложнее, чем «просто скопировать пикер титула»
(из-за toggle-удаления и эвристики сопоставления), но без новых Entity/DTO, без бэкенд-правок,
без миграций. Полноценная техспека оправдана — новых технических развилок для Системного
аналитика уже не осталось (все закрыты выше), но точный контракт функций (сигнатуры, порядок
токенов при удалении из середины строки, что происходит с хвостовым комментарием при
toggle-удалении соседнего токена) стоит зафиксировать письменно перед реализацией.
