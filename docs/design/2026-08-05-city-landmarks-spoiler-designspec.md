# Дизайн-спека: «Значимые места» — блок спойлеров

**Дата:** 2026-08-05 · **Роль:** Дизайнер · **База:** [техспека](2026-08-05-city-landmarks-spoiler-techspec.md) (Т1–Т5)

Технический контракт (JS-массив состояния, поштучные PUT, разметка по
элементам) уже зафиксирован в техспеке — здесь только форма подачи: какие
классы вводятся, какие переиспользуются готовыми, как выглядят состояния
(свёрнуто/развёрнуто/пусто/ошибка). Закрывает открытый вопрос Т5.

Правило для всей спеки: **новых кнопочных стилей не вводим** — весь набор
действий (Сохранить / Отмена / Удалить) уже есть в проекте как семья
`.chr-modal-btn` + модификатор (`.create`/`.cancel`/`.danger`), с общим
box-model (`padding: 4px 10px`, `--f-heading`, uppercase) и уже
touch-safe (в списке `@media (pointer: coarse)`, `styles.css:2894`). Ни
техспека, ни этот документ не изобретают `.btn-danger`/второй «Сохранить» —
там, где в техспеке был плейсхолдер `.btn-submit`/`.btn-danger`, ниже —
финальный класс.

## 1. Карточка записи — `.city-landmark-item`

```
┌─────────────────────────────────────────────────────┐
│ ▸ Опера Гарнье                                       │  ← свёрнуто, .city-landmark-summary
└─────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────┐
│ ▾ Опера Гарнье                                       │  ← развёрнуто
│                                                       │
│ [ Опера Гарнье                                    ]  │  ← .form-control, name
│ [ Главный Элизиум, вотчина Князя…                  ]  │  ← .form-control, textarea, desc
│                                                       │
│                                  [Сохранить] [Удалить]│  ← .city-landmark-item-actions
└─────────────────────────────────────────────────────┘
```

**Не наследует `.city-create-spoiler` напрямую** (техспека Т5 уже отметила
эту развилку) — тот класс несёт `uppercase`/`letter-spacing: .1em`/`gold`,
уместные для заголовка-рубрики («ПРАВИЛА И ОГРАНИЧЕНИЯ ГОРОДА»), но не для
собственного имени места: капсом «ОПЕРА ГАРНЬЕ» читается как кричащий
лейбл, а не как название. Новый класс перенимает у прототипа только
структурную часть (рамка/фон/маркер `▸`/`▾`), меняя типографику на обычный
текстовый регистр:

```css
#city-landmarks-list {
  display: flex;
  flex-direction: column;
  gap: 8px;
  margin-bottom: 10px;
}

.city-landmark-item {
  border: 1px solid var(--border);
  border-radius: var(--r-sm);
  background: var(--bg2);
}

.city-landmark-summary {
  padding: 11px 14px;
  cursor: pointer;
  list-style: none;
  font-family: var(--f-body);
  font-size: var(--fs-body);
  color: var(--text2);
  transition: color .15s;
}

.city-landmark-summary::-webkit-details-marker {
  display: none;
}

.city-landmark-summary::before {
  content: '▸ ';
  color: var(--text3);
}

.city-landmark-item[open] > .city-landmark-summary::before {
  content: '▾ ';
}

.city-landmark-item[open] > .city-landmark-summary {
  color: var(--text);
}

.city-landmark-summary:hover {
  color: var(--gold2);
}

.city-landmark-body {
  padding: 0 14px 14px;
  display: flex;
  flex-direction: column;
  gap: 8px;
}

.city-landmark-item-actions {
  display: flex;
  gap: 8px;
  justify-content: flex-end;
}
```

- Маркер `▸`/`▾` и логика hover — **буквально та же пара правил**, что
  `.city-create-spoiler`/`summary::before` (`styles.css:2372-2379`), только
  без `text-transform`. Не второй способ рисовать спойлер в проекте — тот
  же приём, другая типографика поверх.
- `color: var(--text2)` в покое / `var(--text)` в открытом состоянии —
  открытая запись чуть контрастнее закрытых, глазу проще найти, какая
  сейчас развёрнута, без дополнительной рамки-акцента.
- Название полей внутри (`.form-control` для строки и для textarea) — тот
  же класс, что уже используют текстовые поля формы города
  (`city-leitmotif`, `city-specifics` и т.д.) — узнаваемый инпут, не
  `.hooks-input` (тот компонент — горизонтальная пара полей в одну строку,
  здесь поля стоят вертикально одно под другим, `.form-control` для этого
  и предназначен).
- Кнопки действий — `<button class="chr-modal-btn create city-landmark-save-btn">✓ Сохранить</button>`
  и `<button class="chr-modal-btn danger city-landmark-del-btn">🗑 Удалить</button>`,
  прижаты вправо (`justify-content: flex-end`) — так уже стоит пара
  Edit/Delete в шапке модалки библиотеки (`.v20-disc-detail-actions`,
  тот же принцип «действия record'а — справа»).

## 2. Пустой список

Без изменений от техспеки — `<div class="cdet-empty">Значимых мест пока
нет</div>` тем же начертанием (курсив, `var(--text3)`), что уже
используется для пустых районов на этой же вкладке. Располагается **над**
кнопкой «+ Добавить запись», а не вместо неё — точка входа для первой
записи должна быть видна сразу.

## 3. Строка создания — переиспользуем «Ключевые точки» 1:1

```
┌───────────────────┬───────────────────────────────┬───┬────────┐
│ [ Название…      ] │ [ Описание…                 ] │ ✓ │ Отмена │
└───────────────────┴───────────────────────────────┴───┴────────┘
                          + Добавить запись
```

Класс `.hooks-item` + пара `.hooks-input.city-landmark-title-inp`
(`flex: 0 0 30%`) / `.hooks-input.city-landmark-desc-inp` (`flex: 1`) —
**уже существуют в CSS** (`styles.css:6381-6386`, заведены прошлым циклом
специально под этот экран) — нулевые новые правила для самих полей.
Кнопки в этой строке — та же пара классов, что и в п.1:
`.chr-modal-btn.create` (Сохранить) и `.chr-modal-btn.cancel` (Отмена), а
не `.btn-submit`, чтобы весь блок «Значимых мест» говорил одним и тем же
кнопочным языком (создание/правка/удаление — одна визуальная семья, не
три). Порядок в разметке — как в техспеке: поля → ✓ → Отмена, всё внутри
одного `.hooks-item`, значит уже `display:flex; gap:10px` из существующего
правила `.hooks-item` (`styles.css:6299-6303`) — ряд получается сам собой,
без flex-wrap на десктопе.

`id="city-landmark-create-row"` по умолчанию `style="display:none"` —
но раз `.hooks-item` уже `display:flex`, при показе форма должна получать
`style.display = 'flex'` (а не `'block'`, как было в исходном тексте
техспеки Т3 — там `style.display = 'flex'` уже верно указан, фиксирую
здесь как решённый визуальный вопрос, не альтернативу).

Кнопка «+ Добавить запись» — без изменений, `.hooks-add-btn` (уже есть,
`styles.css:6357-6367`), в момент показа формы создания скрывается
(`style.display = 'none'`), чтобы не было двух видимых точек входа в один
процесс одновременно (см. техспеку Т3).

## 4. Состояние сохранения / ошибки — без нового паттерна

- Кнопка, на которую кликнули (Сохранить у записи, Удалить, Сохранить в
  форме создания) — `disabled` на время запроса. Отдельного
  текста-затычки («⏳ Сохранение…») в этом блоке **не вводим** — в отличие
  от кнопки «Создать домен»/общего «✓ Сохранить» формы редактирования
  (где это один долгий вызов на весь список), здесь действие — быстрый
  point-запрос на одну запись; `disabled` + существующий `:disabled` стиль
  (`opacity: .4`, уже в `.chr-modal-btn:disabled`, `styles.css:5429`)
  достаточно как обратная связь, третий вид индикации загрузки не нужен.
- Ошибка — `showToast(..., 'error')`, как и было. Поля/значения не
  сбрасываются (уже в техспеке Т4) — просто кнопка возвращается в активное
  состояние.
- Подтверждение удаления — `showConfirm(...)`, стандартный оверлей
  проекта, без изменений.

## 5. Доступность

- `<details>`/`<summary>` — нативная семантика раскрытия, работает с
  клавиатуры (Enter/Space на фокусе `summary`) без дополнительного JS —
  тот же плюс, которым уже пользуется `.city-create-spoiler`.
- Touch-цели: `.chr-modal-btn` и `.form-control` уже в списке
  `@media (pointer: coarse) { ... min-height: 44px }` (`styles.css:2894`,
  `:2897`) — новые кнопки/инпуты наследуют это автоматически, никаких
  правок в медиа-запрос не требуется.
- `.city-landmark-summary` (сам `<summary>`) не входит в этот список — как
  и `.city-create-spoiler > summary` сегодня; консистентно с существующим
  поведением проекта для спойлеров (правило CLAUDE.md про 44px касается
  `button`/`a`/`[role=button]`, `<summary>` не подпадает под него ни там,
  ни здесь).

## Приёмка (визуальная, поверх технической из техспеки)

- Свёрнутый список из 2+ записей — видно только названия, ровный отступ
  `gap: 8px` между карточками, никакой рамки вокруг списка целиком (рамка
  — только у каждой записи, не у контейнера).
- Разворот записи — плавно (нативная `<details>`, без своей анимации,
  как и у существующего спойлера) показывает название/описание как
  обычные поля ввода + ряд из двух кнопок справа.
- Строка создания визуально неотличима по стилю полей от «Ключевых точек»
  локации — если оба экрана открыть рядом, разница только в подписях
  плейсхолдеров.
- Ни один новый цвет/шрифт вне уже объявленных переменных `:root` не
  появился — весь набор классов либо переиспользован 1:1, либо собран из
  фрагментов уже существующих правил.
