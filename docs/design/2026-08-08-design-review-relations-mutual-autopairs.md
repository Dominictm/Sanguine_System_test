# Дизайн-ревью: «Взаимно» + авто-пары (Фаза 3)

**Роль:** Дизайнер. **Входные данные:**
[2026-08-08-relations-mutual-autopairs-techspec.md](2026-08-08-relations-mutual-autopairs-techspec.md)
(Системный аналитик, Фаза 3). Разметка/логика уже детально расписаны — UX-аудит поверх готового
технического решения перед передачей Разработчику.

**Аудитория и сценарий:** тот же Рассказчик. Нюанс этой фазы: впервые в этой карточке действие

## 1. Чекбокс «Взаимно» без сенсорной цели на `pointer: coarse`

Техспека §3 не задаёт `@media (pointer: coarse)` для `.cdet-rel-mutual`. В этой же кодовой базе
уже есть прецедент для ровно такого элемента — `<label>`, оборачивающий чекбокс с текстом —
`.graph-filter-chip` (`styles.css:2079-2108`) получает `min-height: 44px` под `pointer: coarse`,
обязательное правило проекта (`CLAUDE.md`) для touch-целей. Нативный чекбокс сам по себе — около
13-16px, без явной высоты `<label>` кликабельная область на телефоне/планшете останется тесной.

**Рекомендация**: добавить в §3 техспеки:
```css
@media (pointer: coarse) {
  .cdet-rel-mutual { min-height: 44px; }
}
```

## 2. Строка чекбокса растягивается на всю ширину — визуально «пустая полоса»

`.cdet-rel-row` — `flex-direction: column`, из-за дефолтного `align-items: stretch` каждый
прямой потомок (включая `.cdet-rel-mutual`) растягивается на всю ширину строки. Чекбокс + слово
«Взаимно» коротки — при растяжении на всю ширину визуально получается почти пустая горизонтальная
полоса с содержимым в левом углу, между плотной шапкой сверху и полем описания снизу. Не критично
(кликабельная область даже больше — это не противоречит находке №1), но выглядит как
недосмотренная вёрстка.

**Рекомендация**: `align-self: flex-start` на `.cdet-rel-mutual` — тогда `<label>` занимает
только своё содержимое, не всю ширину строки:
```css
.cdet-rel-mutual {
  display: flex;
  align-items: center;
  gap: 6px;
  font-size: var(--fs-sm);
  color: var(--text2);
  cursor: pointer;
  align-self: flex-start;
}
```

## 3. Несколько предупреждений синхронизации — один toast со всеми через `; ` нечитаем

Техспека §2.3: `showToast(d.warnings.join('; '), 'warning')`. Если за одно сохранение не
нашлось два-три персонажа-цели одновременно (реалистично — Рассказчик мог опечататься в
нескольких именах подряд, вставляя связи пачкой), пользователь получит один длинный toast вида
«"Мария" не найден(а) среди персонажей — взаимная связь не создана; "Пётр" не найден(а)…» — toast
проекта (`utils.js:74-85`) — компактный, кратковременный (4 секунды по умолчанию) элемент для
ОДНОГО сообщения, не для списка. Длинная строка через `; ` в нём либо обрежется по ширине, либо
потребует читать в спешке до исчезновения — оба варианта хуже, чем несколько отдельных toast'ов.

**Рекомендация**: показывать каждое предупреждение отдельным вызовом `showToast`, не объединяя:
```js
(d.warnings || []).forEach(w => showToast(w, 'warning'));
```
`showToast` уже поддерживает несколько одновременных вызовов (`toast-container` копит несколько
элементов) — специального стекинга городить не нужно.

## 4. Пустое описание у зеркальной связи — пользователю неоткуда узнать, что это норма

Техспека сознательно (§4.4, с обоснованием) оставляет описание зеркальной записи пустым — решение
разумное (не подставлять слова от чужого лица), но открывающий карточку Б Рассказчик увидит
связь с типом «Чайлд» и совсем пустым описанием — неотличимо на глаз от «кто-то забыл заполнить»
или бага. В карточке уже есть устоявшийся паттерн для этой ситуации — «пусто, но это ожидаемо»
уже стилизуется отдельно от «пусто как баг»: `.cdet-val.unknown` (`styles.css:3594-3598`,
приглушённый `--text3`, курсив, `opacity: .55`).

**Рекомендация**: в просмотре (§2.4 техспеки, обе точки правки) — если `r.mutual` и
`!r.description`, показывать вместо `.cdet-rel-desc` **чисто визуальную** подсказку тем же
стилем, что `.cdet-val.unknown` — не записывать её на диск (это не изобретённая пользователем
формулировка, а пояснение механизма, у него другая природа, поэтому хранить как настоящее
описание не нужно):
```js
const descHtml = (r.mutual && !r.description)
  ? '<div class="cdet-rel-desc cdet-rel-desc-auto">Добавлено автоматически по взаимной связи — можно уточнить описание</div>'
  : `<div class="cdet-rel-desc">${escHtml(r.description)}</div>`;
```
```css
.cdet-rel-desc-auto {
  color: var(--text3);
  opacity: .55;
}
```
(наследует `font-style: italic` от уже существующего `.cdet-rel-desc` — переопределять не нужно).
