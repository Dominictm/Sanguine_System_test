# Дизайн-спека: реструктуризация формы «Создать новый домен»

**Дата:** 2026-08-04 · **Роль:** Дизайнер · **База:** [workplan](2026-08-04-city-create-form-restructure-workplan.md) · [техспека](2026-08-04-city-create-form-restructure-techspec.md) (T1–T5)

Технический контракт (какие ключи/атрибуты/JS) уже зафиксирован в техспеке —
здесь только форма подачи: расположение, иерархия, отступы, состояния.
Новых компонентов не вводится — весь дизайн собирается из уже существующего
языка формы (`.city-create-section-label`, `.city-create-spoiler`,
`.form-group`/`.form-label`, `.field-tip`), чтобы не плодить второй визуальный
диалект рядом с уже устоявшимся.

---

## 1. Информационная архитектура

**Было** (11 смысловых блоков подряд, без разделения по важности для старта):

```
Название/Год → Сеттинг → Фракции → Политический ландшафт → География
→ «Значимые места города» (=Ключевые локации) → Лейтмотивы → Специфика
→ Чего избегать → Источники → [Правила и ограничения, свёрнуто] → Создать
```

**Стало** (T1/T2/T4 убирают 3 блока, T3 группирует хвост) — форма читается
как воронка «кто → о чём говорим → как звучим → техническая тонкая настройка»:

```
1. Название/Год          — идентификация домена (обязательное)
2. Сеттинг                — общее описание (что это за город)
3. Фракции                 — с кем работаем (уже структурный редактор, не трогаем)
4. Голос и стиль хроники   — Лейтмотивы / Специфика / Чего избегать / Источники (T3, развёрнуто)
5. Правила и ограничения   — 7 полей минус «Значимые места» (T4, свёрнуто, как было)
6. [Создать домен]
```

Смысл перестановки: то, что нужно **прямо на старте** (имя, о чём город,
кто действующие лица) — видно сразу. То, что определяет **как AI говорит**
об этом городе (голос) — второй по важности блок, тоже сразу видно, но уже
без структурных данных (расклад сил/география/точки), которых на старте
обычно ещё нет. Технические лимиты генерации — по-прежнему последними и
свёрнуты, это тонкая настройка для тех, кому она сейчас нужна, а не
обязательный шаг.

## 2. Раздел T3 — «Голос и стиль хроники»

**Компонент:** повторяет уже существующий `.city-create-section-label`
(тот же, что был у «Политического ландшафта»/«Географии» до их удаления) —
никакого нового CSS-класса не требуется.

```
┌─────────────────────────────────────────────┐
│ ─── ГОЛОС И СТИЛЬ ХРОНИКИ ⓘ                  │  ← .city-create-section-label
│                                               │     (border-top 1px var(--border),
│  Лейтмотивы и атмосфера ⓘ                    │      margin 20px 0 10px,
│  [ textarea, 3 строки ]                      │      padding-top 12px,
│                                               │      gold, uppercase, letter-spacing .04em)
│  Специфика ответа ⓘ                          │
│  [ textarea, 3 строки ]                      │
│                                               │
│  Чего избегать ⓘ                             │
│  [ textarea, 3 строки ]                      │
│                                               │
│  Источники ⓘ                                 │
│  [ textarea, 2 строки ]                      │
└─────────────────────────────────────────────┘
```

- Заголовок раздела **не** `<details>` — все 4 поля видны сразу без клика.
  Обоснование уже в техспеке: это голос Рассказчика с первой сцены, не
  опциональная деталь, прятать его наравне с «Ограничениями генерации» —
  занижает его значимость в глазах заполняющего форму.
- `data-tip` заголовка: «Лейтмотивы, специфика ответа, чего избегать,
  источники — то, что формирует голос Рассказчика для этого города».
  Короткая, в один присест читаемая фраза — по образцу уже существующих
  тултипов формы (сравнить длину с тултипом «Политический ландшафт», ныне
  удаляемым, — не длиннее).
- Внутренние 4 поля — без изменений (те же `.form-group`/`.form-label`/
  placeholder-тексты, что сегодня).

## 3. Раздел T5 — «Правила и ограничения города» в форме редактирования

Сейчас в форме создания это уже собранный, рабочий паттерн
(`#city-create-rules`, классы `.city-create-spoiler.city-create-subspoiler`)
— переносим его **один в один** в форму редактирования, без визуальных
отличий (пользователь, знакомый с формой создания, должен узнать блок).

```
┌─────────────────────────────────────────────┐
│ ▸ ПРАВИЛА И ОГРАНИЧЕНИЯ ГОРОДА               │  ← .city-create-spoiler
└─────────────────────────────────────────────┘     (closed by default)

           ↓ клик по summary

┌─────────────────────────────────────────────┐
│ ▾ ПРАВИЛА И ОГРАНИЧЕНИЯ ГОРОДА               │
│                                               │
│  Значимые места ⓘ                            │
│  [ textarea, предзаполнено, 2 строки ]       │
│  Охотничьи угодья ⓘ                          │
│  [ ... ]                                     │
│  Законы домена ⓘ  /  Смертные институции ⓘ   │
│  Календарь города ⓘ  /  Технологии... ⓘ      │
│  Ограничения генерации ⓘ  /  Именник... ⓘ    │
└─────────────────────────────────────────────┘
```

**Отличие заголовка от формы создания:** без суффикса «(необязательно)».
В форме создания это слово важно — сигнализирует «можно пропустить при
первом заполнении». В контексте редактирования уже существующего города
это не про необязательность ввода, а просто про сворачиваемую техническую
группу — постоянное «(необязательно)» там читалось бы странно, особенно
если поля уже заполнены. Заголовок: **«Правила и ограничения города»**.

**Состояние по умолчанию:** свёрнуто (`▸`), даже если поля уже заполнены —
симметрично форме создания, и потому что просмотр (`_renderCityView`) уже
показывает те же данные текстом до захода в режим редактирования — не
нужно дублировать открытый вид дважды.

**Позиция в разметке:** последним блоком внутри панели «Поля», после всех
остальных секций (`${fieldRows}`) и перед footer'ом кнопок «Сохранить/
Отмена» — так же, как в форме создания раздел правил идёт последним перед
кнопкой «Создать домен».

**Внутренняя раскладка 7 полей:** одна колонка, сверху вниз, в порядке
`CITY_RULE_SECTIONS` (landmarks/hunting/edicts/mortals/calendar/tech/
limits/naming минус landmarks уже исключён из create, но **в edit
присутствует первым** — «Значимые места» открывает список, т.к. это
единственное поле из восьми, которого на старте нет вообще нигде в форме
создания, логично, что в дальнейшем оно первым бросается в глаза при
редактировании). Двухколоночная сетка не нужна — поля разной длины
текста, а форма уже вертикальная по всей длине (не вводить исключение
ради одного блока).

## 4. Состояния и доступность

- **Hover/focus заголовка-спойлера** — уже покрыто существующим правилом
  `.city-create-spoiler > summary:hover { color: var(--gold2) }` — новых
  правил не требуется, класс переиспользуется как есть.
- **Touch-target** — `summary` уже имеет `padding: 14px 0` поверх текста
  на `var(--fs-base)` — фактическая кликабельная высота ≥44px, требование
  проекта (`CLAUDE.md` п.5 для веб-правок) выполняется автоматически за
  счёт переиспользования класса, отдельно проверять не нужно.
- **Пустое состояние** (create, 4 поля «Голоса и стиля») — как и сегодня:
  placeholder-текст в каждой textarea, без плейсхолдера-затемнения всего
  блока — раздел не выглядит «неактивным», потому что он не опционален.
- **Заполненное состояние** (edit, «Правила и ограничения») — при наличии
  текста в любом из 7 полей блок всё равно закрыт по умолчанию (см. §3) —
  никакого визуального индикатора «внутри есть данные» на самом
  `summary` не добавляется (сознательно: превратилось бы в отдельную
  фичу-бейдж, которой нет ни у одного другого `<details>` в проекте —
  не по объёму этой задачи).

## 5. Что осознанно не меняется

- Цвета, шрифты, токены — ни одного нового `--fs-*`/`#hex`/размера не
  вводится, всё через уже существующие переменные и классы.
- `.city-district-card`/`_cityDistrictsEditEditorHtml` (карточки района) —
  визуально не меняются, T2 их не показывает в форме создания, но сама
  карточка (используется постфактум на странице города) остаётся как есть.
- Разметка `.form-group`/`.form-label`/`.field-tip` внутри каждого
  отдельного поля — без изменений везде, где поле просто переезжает
  (T3) или получает новый режим адресации (T5, `data-city-field` вместо
  `id` — на вид не влияет, см. техспеку).

## Приёмка (визуальная, поверх технической из техспеки)

- Форма создания за один экран без скролла ощутимо короче текущей (минус
  3 блока: Политический ландшафт, География, Ключевые локации).
- «Голос и стиль хроники» визуально неотличим по весу заголовка от
  оставшихся «Фракций» — не выглядит второстепенным.
- Блок «Правила и ограничения города» в редактировании визуально — тот
  же компонент, что пользователь уже видел при создании города (не два
  разных спойлера в одном проекте).
