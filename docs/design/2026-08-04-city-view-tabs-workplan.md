# План: вкладки в форме просмотра города

**Дата:** 2026-08-04 · **Роль:** Аналитик · **Статус:** план, к реализации не приступали

## Контекст

Сейчас `_renderCityView()` (`web/public/scripts/city.js`) не структурирует
содержимое города вовсе — берёт `city.md` целиком (за вычетом H1) и рендерит
одним блоком через `mdToHtmlBlock(body)`. Единственное структурное
исключение — блок районов (`_cityViewDistrictsHtml()`, карточки с
привязкой локаций). Задача — развернуть просмотр в 4 вкладки с явным
покрытием по полям, аналогично тому, как уже структурирована форма
редактирования (`CITY_SECTION_DEFS`).

## Уточнения, снятые в этом заходе

Три пункта из присланного списка не покрывали весь набор канонических
секций `city.md` (`web/lib/parsers/city.js` → `CITY_SECTIONS`, 16 ключей) —
решения зафиксированы:

1. **«Правила и ограничения города»** (вкладка «Общая») — не отдельная
   секция с собственными данными, а **контейнер для полей, оставшихся
   без отдельной строки**: Смертные институции, Ограничения генерации,
   Именник и фактура. Законы домена / Календарь города / Технологии и
   Маскарад остаются отдельными строками той же вкладки, как в исходном
   списке — задваивания с контейнером нет, потому что контейнер их больше
   не включает.
2. **Значимые места** — присланы дважды под разными именами: в «Общей»
   (как «Значимые места», с редизайном под карточки) и в «Географии» (как
   «Отмеченные локации»). В коде это одно и то же поле `landmarks` —
   отдельного понятия «отмеченные локации» нет. Решение: поле переезжает
   **целиком в «Географию»** — там оно логичнее среди районов/локаций;
   из «Общей» убирается.

## Открытый пункт, добавленный мной (не было в присланном списке)

**«Сеттинг» (`description`)** — вступительный абзац `city.md` под H1, не
входит в `CITY_SECTIONS`, но существует как отдельное поле формы
создания/редактирования. В присланном списке вкладок этого поля нет ни в
одной из четырёх. По умолчанию ставлю его в «Общую», сразу после
Название/Год (тот же порядок, что в форме редактирования) — если это не
то место, где его нужно видеть, поправить перед техспекой.

## Функциональные требования

### Редизайн «Значимые места» (карточки, вкладка «География»)

Сейчас `landmarks` — обычный текст (буллет-лист, как остальные текстовые
секции). Новый формат — повторяемые записи «название + описание» с
Сохранить / Добавить запись / Удалить запись, прямо на странице просмотра
(без входа в общий режим редактирования города — по аналогии с тем, как
уже работают карточки районов в этой же вкладке: интерактивны сразу в
просмотре, не только в `_renderCityEdit`).

**Технический прецедент в этом же проекте** — идентичная задача уже
решена для «Ключевых точек» локации (`web/public/scripts/locations.js`,
`_collectLocDetKeyPoints`/`keyEditHtml`, цикл 2026-08-02..04): повторяемые
строки `место + описание`, собираются в markdown-таблицу
`| Место | Описание |`. Для «Значимых мест» города напрашивается тот же
формат — `| Название | Описание |` вместо буллет-листа. Меняет формат
хранения секции `## Значимые места` в `city.md` (сейчас буллеты — нужна
миграция для городов, где секция уже заполнена буллетами не по формату
таблицы; проверить на Париже — секция сейчас пустая, `- …`, риска для
реальных данных нет, но упомянуть в техспеке явно).

### Остальные вкладки — read-only рендер существующих структур

«Политика» и «Фракции» **не вводят новых данных** — это уже существующие
под-структуры секций `political`/`factions` (те же, что показывает форма
редактирования через `_cityPolEditorHtml`/`_cityFactionsEditorHtml`), но
здесь — **без input-полей**, просто отображение (карточка/список), без
кнопок сохранения. Редактирование этих данных остаётся в форме
редактирования — просмотр только показывает.

Аналогично для текстовых полей «Общей» — просто вывод текста секции
(`mdToHtmlBlock` на конкретную секцию, не весь `city.md`), без формы.

### Что не входит в этот цикл

- Изменение формы **редактирования** — не трогаем, она уже структурирована
  отдельным циклом (T1–T5, `2026-08-04-city-create-form-restructure-*`).
  Если вкладочная структура просмотра должна зеркально появиться и в
  редактировании — отдельный запрос.
- Само редактирование текстовых полей на странице просмотра (кроме
  «Значимых мест», для которых явно попросили CRUD) — не добавляется:
  пользователь описал функционал сохранения только для «Значимых мест».

## Порядок реализации (предложение для передачи дальше)

1. Каркас вкладок (`_renderCityView` → таб-бар + 4 панели, по образцу уже
   существующего `.city-edit-tabs`/`.cdet-tab-bar` из формы редактирования)
   — независимая, самая первая задача.
2. Вкладки «Общая» (без группы правил), «Политика», «Фракции» — read-only
   рендер существующих данных, без новых форматов хранения. Параллельно
   друг другу.
3. Группа «Правила и ограничения города» внутри «Общей» — тривиальная
   после (2), тот же read-only паттерн, просто 3 поля под одним
   заголовком/спойлером.
4. «Значимые места» (карточки, CRUD) — отдельная, самая крупная задача:
   новый формат хранения секции + API для Сохранить/Добавить/Удалить.
   Делать последней — самая рискованная (меняет формат данных).
