# Дизайн-спека: удаление/редактирование в Библиотеке + вкладка «Сородичи»

**Дата:** 2026-08-04 · **Роль:** Дизайнер · **База:** [workplan](2026-08-04-library-kindred-workplan.md) · [техспека](2026-08-04-library-kindred-techspec.md) (K1–K6)

Технический контракт (какие функции/эндпоинты/DOM-узлы) уже зафиксирован —
здесь форма подачи. Разбор существующих стилей (`styles.css`) даёт почти
всё нужное готовым — новых токенов/цветов не требуется нигде, кроме одной
новой раскладки шапки детейл-модалки.

## 1. Находка: карточка секты на клане — уже есть готовый класс

`.lib-card-sect` (`styles.css:10045-10060`) уже существует и делает ровно
то, что нужно карточке клана — бейдж с золотой обводкой, uppercase,
`var(--gold)`, сейчас используется для пометки «факт биографии доступен
только Шабашу» и т.п. Карточка клана (K5) переиспользует его один в один
для секты — не изобретать вторую версию того же бейджа:

```
┌─────────────────────┐
│ 🧛 Тремер            │
│                       │
│  [ КАМАРИЛЬЯ ]        │  ← .lib-card-sect, тот же класс
└─────────────────────┘
```

## 2. Шапка единой детейл-модалки (K1) — раскладка Edit/Delete

Сегодня `.v20-disc-detail-head` — просто `flex; justify-content:
space-between` строка «название ↔ мета» (клан/категория дисциплины и
т.п.), без кнопок. Кнопки правки/удаления **не пришиваются отдельным
блоком поверх модалки** (в отличие от персонажа, где `.cdet-delete-btn`
абсолютно спозиционирована в sticky-шапке — у `.v20-disc-modal` нет
sticky-шапки, весь контент скроллится одним блоком) — они становятся
третьим элементом той же flex-строки:

```
┌──────────────────────────────────────────────────┐
│  Тремер                          [✏ Редактировать] [🗑]  │  ← .v20-disc-detail-head
│  Камарилья                                         │     (расширенная)
├──────────────────────────────────────────────────┤
│  Дисциплины: Аспект, Доминирование, Тауматургия    │
│  Слабость: …                                       │
│  …                                                  │
└──────────────────────────────────────────────────┘
```

**Визуальный язык кнопок — переиспользуется 1:1** с уже существующей
парой в шапке персонажа (`.cdet-edit-btn`/`.cdet-delete-btn`,
`styles.css:3589-3626`), только без `position: absolute` (тут они —
обычные flex-элементы, не наложение на sticky-хедер):
- **✏ Редактировать** — `border: 1px solid var(--border)`, hover/active →
  золотая обводка + `rgba(184,134,11,.08)` фон (`.cdet-edit-btn.active`,
  уже готовое состояние «в режиме правки»). Переключение текста на
  **✓ Сохранить** — тот же элемент, тот же `.active`-класс, просто другая
  подпись, а не два разных визуальных языка кнопки.
- **🗑** — `color: var(--c-danger-text)`, без рамки, тот же красный акцент,
  что у удаления персонажа — библиотека не придумывает свой оттенок
  «опасного» действия.

**Новый CSS** — только сама раскладка (класс `.cdet-edit-btn`/
`.cdet-delete-btn` уже есть, `position: absolute` в них снимается через
модификатор для этого контекста, не трогая персонажа):
```css
.v20-disc-detail-head {
  /* существующее flex/justify-content/gap не меняется */
}
.v20-disc-detail-actions {
  display: flex;
  gap: 8px;
  flex-shrink: 0;
}
/* .cdet-edit-btn/.cdet-delete-btn внутри этого контейнера — без
   position:absolute (тот модификатор специфичен для sticky-шапки
   персонажа), просто обычные inline-кнопки в общем flex-потоке. */
.v20-disc-detail-actions .cdet-delete-btn {
  position: static;
}
```
Для канонических записей (K1, custom=false) `.v20-disc-detail-actions` не
рендерится вовсе — заголовок остаётся как сегодня, без изменений разметки
для канона (нулевой визуальный «шум» там, где действие недоступно).

## 3. Режим правки внутри детейл-модалки

**Поля формы — тот же класс, что уже использует `#lib-edit-modal`**
(`.chr-form-group`/`.chr-form-label`/`.chr-form-input`) — раз K1
технически рендерит те же поля тем же конфигом (`_LIB_KIND_CONFIG`) внутри
`#v20-disc-modal-body`, они и выглядят как форма создания/правки, которую
пользователь уже видел через «+ Добавить» — не второй визуальный язык
формы в одном и том же диалоге редактирования библиотеки.

```
┌──────────────────────────────────────────────────┐
│  [Тремер________________]        [✓ Сохранить] [🗑]│
│                                                     │
│  Секта                                             │
│  [Камарилья ▾]                                     │
│                                                     │
│  Дисциплины                                        │
│  [Аспект, Доминирование, Тауматургия_____________] │
│                                                     │
│  Слабость                                          │
│  [___________________________________________]     │
│  …                                                  │
└──────────────────────────────────────────────────┘
```
Название переезжает из статичного `<h3>` в `.chr-form-input` (тот же
приём, что уже делает `char-detail.js` при входе в `_enterInfoEdit` —
`#cdet-name-input` заменяет статичное имя персонажа) — не третий способ
редактирования заголовка записи в проекте.

🗑 остаётся видимой и активной и в режиме правки (можно передумать
редактировать и сразу удалить) — не прячется на время редактирования.

**Ошибка сохранения** — та же плашка, что в `#lib-edit-modal` сегодня
(`#lib-edit-error`, красный текст под последним полем) — не тост, не
alert: пользователь остаётся внутри формы и видит, что именно не так,
рядом с полями, которые нужно поправить.

## 4. Диалог «Сохранить перед закрытием?»

Готовый компонент `showConfirm()` — без изменений визуально (тот же
`#confirm-overlay`/`.confirm-box`, что уже используют все подтверждения в
проекте). Единственное, что задаёт K1 — конкретные подписи кнопок:
`confirmText: 'Сохранить'`, `cancelText: 'Не сохранять'` — не generic
«Да/Нет», раз оба исхода равноценны (оба закрывают модалку) и подпись
должна прямо называть, что произойдёт при каждом клике.

Диалог удаления (🗑) — тот же `showConfirm()`, `danger: true` (уже даёт
красный акцент подтверждающей кнопке, как во всех остальных
подтверждениях удаления в проекте — персонаж, локация, город).

## 5. Карточки — что визуально убирается (K2)

`.lib-card-actions` (карандаш/корзина поверх карточки, верхний правый
угол) и `.lib-card-wrap`-обёртка ради них — убираются у всех пяти
категорий. Карточка снова становится единственным `<button>` без
надстроек — короче DOM, ровно тот же `.lib-card`, что уже есть у
неавторских записей сегодня (у custom-записей карточка визуально
**становится проще**, не сложнее — источник правды на «можно править» уже
не карточка, а шапка модалки).

`.lib-card-custom-badge` («✏️ Авторское») **остаётся на карточке** — это
не действие, а статус-метка (аналог `.lib-card-sect`), информирует до
клика, что запись можно будет редактировать — не убирается вместе с
кнопками действий.

## 6. Страница «Сородичи» (K5) — визуально клон «Библиотеки»

Ни одного нового класса — `.page-header`/`.tab-bar`/`.tab-btn`/
`.lib-add-row`/`.lib-panel`/`.lib-cards` переносятся как есть. Единственное
отличие от «Библиотеки» — нет второго уровня вкладок (не
`.disciplines-subtab-bar`), потому что у «Кланов»/«Сект» нет
внутригруппового деления, которое было у дисциплин (Пути/Комбо/etc.).

Иконка пункта меню — `🩸` (капля крови, единственный «природный» символ
для «Сородичи» в палитре уже используемых эмодзи-иконок сайдбара — рядом
с 🎭 «Персонажи», 🗺️ «Фракции»; не переиспользовать 🎭, чтобы не путать
со страницей персонажей).

## 7. Новые поля формы (K3/K4) — «Дисциплины клана» / «Слабость»

Два новых `data-lib-field`-слота в `#lib-edit-modal`, тем же паттерном,
что уже существующие (`clans`/`source`/`note`/`description` —
`index.html:812-839`, каждый — `.chr-form-group` с `.chr-form-label` +
`.chr-form-input`/`.chr-form-textarea`):
```html
<div class="chr-form-group" data-lib-field="discipline-list">
  <label class="chr-form-label" for="lib-edit-disciplines">Дисциплины клана</label>
  <input class="chr-form-input" id="lib-edit-disciplines" autocomplete="off">
</div>
<div class="chr-form-group" data-lib-field="weakness">
  <label class="chr-form-label" for="lib-edit-weakness">Слабость</label>
  <textarea class="chr-form-input chr-form-textarea" id="lib-edit-weakness" rows="2"></textarea>
</div>
```
«Секта» клана — не новый тип поля, `category-select` уже существует
(`index.html:820-823`) — просто ещё один вызов `_libFillCategorySelect`
с опциями из 7 сект вместо merits/flaws/backgrounds-категорий. Один
визуальный `<select>`-паттерн на все «выбор из ограниченного списка» поля
формы, не два.

## Приёмка (визуальная, поверх технической из техспеки)

- Кнопки ✏/🗑 в шапке детейл-модалки визуально неотличимы по стилю от
  уже знакомых кнопок в шапке карточки персонажа — тот же красный/золотой
  акцент, тот же hover.
- У канонических записей шапка выглядит ровно как сегодня (без пустого
  места на месте кнопок — сравнить do/after скриншотом).
- Форма правки внутри детейл-модалки неотличима по стилю полей от формы
  «+ Добавить» — сравнить рядом.
- Карточка клана показывает секту тем же бейджем, что уже показывает
  секто-ограниченный факт биографии — не выглядит как новый элемент
  интерфейса.
- Страница «Сородичи» на первый взгляд неотличима по вёрстке от
  «Библиотеки» (тот же ритм отступов, та же сетка карточек) — узнаваема
  сразу, без обучения.
