## Задача

Создать реальные карточки титулов в `system/library/titles/<slug>.md` на основе
уже собранных и структурированных сырых данных из вики World of Darkness.

**Тип задачи:** [x] Новая фича (наполнение данными)

**Источник данных:** `docs/design/2026-08-06-library-titles-data.md` — полный
свод по 11 категориям (Камарилья, Шабаш, Анархи, Тал'махе'Ра, Инконню, Аширра,
Ассамиты, Тремеры, Цимисхи, Ревенанты, Общие), для каждого титула: предлагаемый
`finalSlug`, ссылка на статью-источник, сырой текст источника в `<details>`
(или пометка «Текста нет»), пометки негативных титулов и коллизий имён.

**Формат карточки** (см. `docs/design/2026-08-06-library-titles-techspec.md`
§2 — точный контракт полей) и живой образец — уже созданные (и с тех пор
удалённые как тестовые) записи имели вид: markdown-заголовок с именем,
`- **Принадлежность:** ...`, опционально `- **Негативный титул:** да`,
`## Описание`. **Перед стартом обязательно прочитай `web/lib/titles.js`**
(реализованный парсер) — он задаёт точный формат, который нужно соблюсти
буквально (иначе карточки не распарсятся).

---

## Контекст

Это **контент-райтинг**, не инженерная задача в чистом виде — но выполняется
тем же образом (создание файлов по образцу, без ручной работы в вебе).
Главное требование: **текст описания переписывается своими словами**, не
копируется дословно из источника (устоявшаяся конвенция проекта — та же,
что применялась при контент-райтинге 34 карточек кланов в этой же сессии
ранее). Источник в data.md — сырой вики-текст, вспомогательный материал для
понимания сути титула, не готовый текст карточки.

**Файлы для чтения перед стартом:**
- `AGENT_BRIEF.md`
- `docs/design/2026-08-06-library-titles-data.md` — источник данных (весь документ)
- `docs/design/2026-08-06-library-titles-techspec.md` §2 — контракт формата карточки
- `web/lib/titles.js` — актуальный парсер (точный формат полей)
- 1-2 уже существующих карточки клана/секты (`system/library/clans/*.md`,
  `system/library/sects/*.md`) — эталон стиля и объёма текста для `## Описание`

## Ограничения

- НЕ трогать `web/.env`
- НЕ менять код (`web/lib/titles.js`, роуты, фронтенд) без крайней необходимости
  — инфраструктура уже реализована и протестирована; если найдёшь баг парсера,
  который мешает наполнению — почини точечно и опиши в отчёте, но не рефактори
  без повода
- НЕ копировать текст источника дословно — переписывать своими словами
  (см. «Контекст» выше)
- Канонные факты WoD (описание титула, его смысл, к какой фракции относится)
  — только по источнику из data.md; при действительной нехватке источника
  (записи без текста — см. data.md §5, 11 записей) не выдумывать лор, а
  писать короткое нейтральное описание на основе одного названия титула
  и его принадлежности, либо пометить `⚠️ Требуется уточнение` в теле
  описания, если даже этого недостаточно
- Обрати внимание на §2 «Открытые вопросы» и §4 «Коллизии» документа-источника
  — по коллизиям slug'ов уже есть готовое решение (`finalSlug` в данных),
  используй его как есть, не изобретай свои slug'и
- НЕ заводить записи с пустым `## Описание` — если данных совсем нет,
  писать минимальный, но осмысленный текст (см. пункт выше)

## Критерии готовности

- [ ] Все ~91-102 записи из data.md (за вычетом явных дублей/нерешённых
  edge-кейсов — см. ниже) заведены как `.md`-карточки в `system/library/titles/`
- [ ] Каждая карточка проходит парсинг `web/lib/titles.js` без ошибок
  (проверить через `GET /api/library/titles` после перезапуска сервера —
  должен вернуть все записи, ни одна не должна выпасть из-за формата)
- [ ] Поле «Принадлежность» заполнено для каждой карточки (секта/клан/род
  — что применимо, см. открытый вопрос 1 в data.md §2 — принадлежность НЕ
  всегда секта, это ОБЫЧНЫЙ текст, не строгий список)
- [ ] Негативные титулы помечены флагом (см. data.md — где стоит «⚠️
  негативный титул»)
- [ ] Тексты описаний — переписаны своими словами, не копипаста источника
- [ ] Линтер карточек не падает: `node system/schema/validate_cards.js`
  (титулы вне его контракта, но команда не должна падать с ошибкой)
- [ ] `npm test` в `web/` без новых падений
- [ ] Живая проверка в браузере (скилл `run-sanguine-web`): вкладка «Титулы»
  открывается, показывает все записи, карточки кликабельны, бейдж
  «Негативный титул» виден там, где нужно
- [ ] `web/tests/report.html` не закоммичен как часть диффа
