# Аналитика: перенос «Сородичи» внутрь «Библиотеки»

**Дата:** 2026-08-05 · **Роль:** Аналитик · **Запрос:** перенести раздел навигации
«Сородичи» (Кланы/Секты) в «Библиотеку» как вкладку перед «Дисциплинами»; при
выборе этой вкладки — второй уровень вкладок «Кланы»/«Секты», по образцу того,
как «Дисциплины» раскрывают под-вкладки «Дисциплины/Комбо/Колдовство/…».

---

## 1. Executive Summary

Технически это откат навигационного решения из вчерашнего цикла (K5,
2026-08-04): тогда «Сородичи» сделали отдельной страницей верхнего уровня —
по образцу самой «Библиотеки» (`page-header → .tab-bar → .lib-panel`), без
второго уровня вкладок, «потому что он там не нужен» (комментарий в коде,
`web/public/index.html:726-728`). Пользователь считает иначе: Кланы/Секты —
часть единого справочника правил, а не отдельный раздел. Перенос сводится к
трём механическим шагам (убрать пункт меню, переставить разметку под
`#page-library`, добавить второй уровень вкладок) — компонентная база для
этого уже существует в проекте и переиспускается без нового CSS/JS-паттерна.
Риска для данных нет: `web/lib/clans.js`/`sects.js` и API `/api/library/clans`
`/sects` не трогаются, меняется только то, где в DOM лежит кнопка.

## 2. Ключевые инсайты

- **Два готовых паттерна вложенных вкладок уже есть в «Библиотеке», и они
  разные** — выбор между ними не тривиален:
  - «Дисциплины» (`.disciplines-subtab-bar`, `index.html:771-780`) — под-вкладки
    **фильтруют одну и ту же карточную сетку** по типу дисциплины
    (`data-disc-group`), один и тот же `#lib-disciplines-body`, один и тот же
    источник данных (`loadLibrary(group)`).
  - «Достоинства»/«Недостатки»/«Факты биографии» (`.merits-subtab-bar` и
    аналоги) — под-вкладки фильтруют **категорию** внутри одной коллекции,
    та же механика.
  - **Кланы и Секты — не так.** Это две разные коллекции с разными API
    (`/api/library/clans` vs `/api/library/sects`), разными карточками
    (`_libClanCardsHtml` vs `_libSectCardsHtml`, `v20-sheet.js:1408`/`1466`) и
    разными контейнерами (`#lib-clans-body` vs `#lib-sects-body`, уже
    существуют). Это **не фильтр одной сетки**, а именно то, что в проекте
    уже реализовано как отдельные `.tab-panel` с собственным `.tab-bar`
    (пример «Дисциплины» vs «Достоинства» на первом уровне «Библиотеки») —
    то есть пользовательский пример («как под-вкладки Дисциплин») совпадает
    по виду (полоска кнопок под верхним таб-баром), но не по механике
    (Дисциплины — один `data-tab`, один список, фильтр; Кланы/Секты — де-факто
    те же `kin-clans`/`kin-sects`, что уже есть, просто на уровень глубже).
  - Практический вывод: технически проще и надёжнее не имитировать
    `.disciplines-subtab-bar`-фильтр, а **вложить уже существующий второй
    `.tab-bar` (`kin-clans`/`kin-sects`) внутрь одной `.tab-panel` новой
    вкладки «Сородичи»** библиотеки — визуально это и есть «вкладка, при
    выборе которой ниже появляются ещё вкладки Кланы и Секты», ровно как
    просит пользователь, и не требует переписывать рендеринг карточек/API.

- **Почти весь код уже написан и просто использован не в том месте.**
  `_libClanCardsHtml`/`_libSectCardsHtml`/`_v20RenderClanDetail`/
  `_v20RenderSectDetail`/`loadKindred()` (все — `web/public/scripts/v20-sheet.js:1384-1516`),
  обработчики `+ Добавить клан/секту` (`_libWireAddButtons('page-kindred')`,
  `library-authoring.js:290`) и dispatch по клику таб-кнопок (`kin-clans`/
  `kin-sects` уже в общем `.tab-btn`-обработчике, `scripts.js:902-903`) —
  ничего из этого не завязано на существование отдельной страницы
  `#page-kindred`; вся привязка — через `id`/`data-tab`, которые можно
  перенести вместе с разметкой без изменений в JS.

- **Единственное место, которое действительно требует правки JS** —
  `navigate(page)` в `scripts.js:319-320` (`if (page === 'kindred')
  loadKindred();` — вызов исчезнет вместе со страницей, данные вкладки нужно
  будет догружать по клику на «Сородичи» внутри `library`, аналогично тому,
  как «Дисциплины»/«Достоинства» подгружаются по клику на свой `.tab-btn`,
  не по `navigate('library')`), и разбор `#page-${page} .tab-btn` в момент
  переключения страниц (`scripts.js:503`) — он уже общий и ничего не сломает,
  если `kin-clans`/`kin-sects` физически окажутся внутри `#page-library`.

- **Порядок вкладок «перед Дисциплинами»** — чисто вопрос порядка `<button>`
  в разметке (`index.html:762-767`); первая кнопка автоматически становится
  `active` по существующей CSS/JS-конвенции (`.tab-btn.active`,
  `.tab-panel.active`) — значит вкладка «Сородичи» станет **вкладкой по
  умолчанию** при заходе в «Библиотеку», если её просто поставить первой и
  перенести класс `active` на неё. Это не побочный эффект, а прямое следствие
  требования «перед Дисциплинами» — стоит явно подтвердить у пользователя,
  что дефолтная вкладка библиотеки должна смениться (сейчас это
  «Дисциплины»), а не просто визуальный порядок в списке.

## 3. Риски и нюансы

- **Название нового пункта меню библиотеки vs страницы.** Сейчас у
  «Библиотеки» нет общего понятия «раздел» — только плоский `.tab-bar`.
  Если внутри вкладки «Сородичи» будет ещё один `.tab-bar` (Кланы/Секты) —
  получится **трёхуровневая вложенность заголовков** (Библиотека → Сородичи →
  Кланы/Секты), тогда как у «Дисциплин» вложенность двухуровневая
  (Библиотека → Дисциплины [+ под-фильтр]). Нужно решить дизайн этого
  третьего уровня (тот же `.tab-bar`, что и «Дисциплины», или другой
  визуальный вес, чтобы не выглядело как случайное дублирование компонента) —
  это вопрос для роли Дизайнера, не решается на этом этапе.
- **`_libWireAddButtons` вызывается дважды по id контейнера**
  (`'page-library'` и `'page-kindred'`, `library-authoring.js:289-290`) —
  при переносе разметки внутрь `#page-library` вызов для `'page-kindred'`
  станет мёртвым (контейнера с таким id больше не будет) и его нужно убрать,
  а не просто оставить рядом «на всякий случай» (мёртвый код, который система
  не запросит выполнить).
- **Пункт бокового меню `data-page="kindred"`** (`index.html:81-83`) при
  переносе просто удаляется — нужно проверить, не ссылается ли на него тур
  по интерфейсу (`web/public/scripts/tour.js` или аналог) как на шаг тура;
  беглый grep по кодовой базе такого шага не нашёл, но роль Системного
  аналитика/Разработчика должна перепроверить перед удалением, чтобы тур не
  указывал в пустоту.
- **Регресс не в тестах.** `web/tests/all.test.js` покрывает API
  (`/api/library/clans`/`/sects`), не DOM-разметку — перенос вкладки не
  затронет backend-тесты, но потребует ручной/CDP-проверки в браузере (по
  паттерну прошлых циклов, скилл `run-sanguine-web`), а не полагаться на
  `npm test` как единственный сигнал готовности.
- **Документация**, обновлённая вчера под отдельную страницу «Сородичи»
  (`docs/guide.md`, §2 список разделов, §15 «Сородичи», §16 «Библиотека»,
  README.md — таблица разделов) — придётся откатить обратно под структуру
  «одна вкладка внутри Библиотеки» в конце цикла, не забыть в рамках задачи
  на реализацию.

## 4. Рекомендации и план действий

1. **Дизайнеру** — определить визуальное решение для третьего уровня вкладок
   (Библиотека → «Сородичи» → Кланы/Секты): переиспользовать `.tab-bar`
   1:1 (как сейчас у отдельной страницы) или ввести визуально более лёгкий
   вариант (ближе к `.disciplines-subtab-bar`), чтобы не путать пользователя
   с «ещё одной такой же полоской кнопок» сразу под первой.
2. **Разработчику**, после дизайн-решения:
   - `index.html`: убрать `<a data-page="kindred">` из бокового меню
     (строки 81–83); переставить блок `#page-kindred` (730–753) внутрь
     `#page-library` как первую `.tab-panel` (перед `tab-lib-disciplines`),
     добавить кнопку `data-tab="lib-kindred"` первой в верхнем `.tab-bar`
     библиотеки и пометить её `active`, снять `active` с «Дисциплин»;
     `kin-clans`/`kin-sects` заголовки/панели остаются как есть внутри новой
     `.tab-panel`.
   - `scripts.js`: убрать `if (page === 'kindred') loadKindred();`
     (строка 320) и саму страницу `kindred` из навигации; добавить вызов
     `loadKindred()` в существующий `.tab-btn`-обработчик по клику на
     `lib-kindred` (рядом с `lib-disciplines`/`lib-psychics` и т.д.,
     `scripts.js:890-903`), с той же логикой один раз — грузить оба списка
     при первом заходе на вкладку.
   - `library-authoring.js:290`: убрать `_libWireAddButtons('page-kindred')`,
     кнопки «+ Добавить клан/секту» продолжат работать через
     `_libWireAddButtons('page-library')` — они уже физически внутри этого
     контейнера после переноса разметки.
   - `v20-sheet.js` (1384–1516): без изменений — весь код клановой/сектовой
     логики адресуется по `id` контейнеров, которые просто переезжают вместе
     с разметкой.
   - Проверить (grep) отсутствие ссылок на `#page-kindred`/`data-page="kindred"`
     в `tour.js` или аналогичном модуле тура перед удалением пункта меню.
3. **По завершении** — откатить вчерашние правки документации под новую
   структуру: `docs/guide.md` (убрать отдельный §15 «Сородичи», описать
   Кланы/Секты как под-вкладки «Библиотеки» перед «Дисциплинами», убрать
   «Сородичи» из списка разделов §2, перенумеровать разделы обратно),
   `README.md` (убрать отдельную строку «Сородичи» из таблицы разделов,
   упомянуть Кланы/Секты в описании «Библиотеки»).

Готово к передаче Системному аналитику для техспеки (контракт `data-tab`,
точные diff-блоки по файлам) — по обычному порядку ролей этого проекта.
