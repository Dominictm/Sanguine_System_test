## П.4. «Модели AI» → раздельные вкладки «Подключение AI» / «Назначение генераций»

### 4.1 Текущая структура (напоминание, без изменений в этом пункте)

`loadAiSettings()` (`scripts.js:1154-1554`, единая функция на 400 строк, гейтится одним
`_aiSettingsLoaded`) делает 2 fetch (`/api/settings` → `orSettings`; `/api/openrouter/models` →
`orModels`), строит `featOrModels` из `orModels`, читает `featPrefs` из `localStorage`, и рендерит
ОБЕ колонки одним `el.innerHTML`: `.ais-left` (`:1186-1332`, подключение — секции
OpenRouter/OpenAI/Gemini/Claude, поля ключа/OAuth) и `.ais-right` (`:1335-1354`, `.ais-features-section`,
8 карточек `_renderFeatCard`). После рендера — навешивает ~10 обработчиков кликов/инпутов
(`:1359-1554`), все они адресуют элементы внутри `.ais-left` (ключи/OAuth/рестарт) — `.ais-right`
интерактивности не требует сверх того, что уже встроено в `_renderFeatCard`.

### 4.2 Решение: разделение без общего стора

**Две независимые функции, каждая со своим fetch, без общего кеш-объекта между ними:**

```js
let _aiConnectLoaded  = false;
let _aiFeaturesLoaded = false;

async function loadAiConnectTab() {
  if (_aiConnectLoaded) return;
  _aiConnectLoaded = true;
  const el = document.getElementById('ai-connect-content');
  let orSettings = { OPENROUTER_MODEL: '', hasKey: false, hasOpenAIKey: false, hasAnthropicKey: false, claudeOauth: null };
  try { orSettings = await fetch('/api/settings').then(r => r.json()); } catch {}
  el.innerHTML = `<div class="ais-left">...</div>`; // разметка :1186-1332 БЕЗ .ais-restart-section (переезжает в П.6)
  // ... обработчики :1359-1554, которые адресуют .ais-left (ключи/OAuth) — переносятся сюда как есть
}

async function loadAiFeaturesTab() {
  if (_aiFeaturesLoaded) return;
  _aiFeaturesLoaded = true;
  const el = document.getElementById('ai-features-content');
  let orSettings = { /* тот же дефолт */ };
  try { orSettings = await fetch('/api/settings').then(r => r.json()); } catch {}
  let orModels = OR_FREE_MODELS_FALLBACK;
  try { const md = await fetch('/api/openrouter/models').then(r => r.json()); if (md.ok && md.models?.length) orModels = md.models; } catch {}
  const featOrModels = _buildFeatOrModels(orModels);
  const featPrefs = JSON.parse(localStorage.getItem('ai-feature-prefs') || '{}');
  el.innerHTML = `<div class="ais-right">...</div>`; // разметка :1335-1354, 8× _renderFeatCard
}
```

**Почему не общий стор** (закрывает открытый вопрос источника): оба fetch дешёвые
(`/api/settings` — чтение одного JSON-файла настроек, без сетевого похода наружу;
`/api/openrouter/models` — единственный реально «внешний» запрос, нужен ТОЛЬКО «Назначению
генераций», где раньше и был). Общий стор (кешировать `orSettings` в модульной переменной,
шарить между двумя загрузчиками) экономит один дешёвый fetch ценой инвалидационной логики —
нужно отслеживать, протух ли кеш `orSettings` при каждом открытии любой из двух вкладок,
плюс отдельно сбрасывать его при сохранении ключа (см. §4.4). Два независимых fetch — да,
секунда лишнего запроса при первом открытии ВТОРОЙ вкладки в сессии, но ноль инвалидационной
логики и полная независимость модулей (можно открыть «Назначение генераций», ни разу не
заходя в «Подключение AI», и получить корректные актуальные данные). Проект уже не борется за
экономию таких запросов нигде больше (сравни: `loadKindred()`, `loadGuideTab()` и другие
ленивые вкладки — каждая фетчит своё независимо, без общего кеша) — решение соответствует
существующей архитектуре, не вводит новый паттерн.

**`orSettings` нужен ОБЕИМ функциям** — `loadAiConnectTab()` показывает статусы ключей,
`loadAiFeaturesTab()` использует его для бейджей «провайдер не настроен» на карточках функций
(`_renderFeatCard`, сигнатура уже принимает `orModels`/пары — **свериться при реализации**,
использует ли `_renderFeatCard` сейчас `orSettings` напрямую или только `orOrModels`/`pref`; если
не использует — этот fetch в `loadAiFeaturesTab()` можно убрать, но по умолчанию оставляем для
консистентности с текущим поведением, где `.ais-right` рендерится в контексте с уже
загруженным `orSettings`).

### 4.4 Сброс кеша после изменения ключа/OAuth — общий helper

Текущий код сбрасывает `_aiSettingsLoaded = false` в 7 местах (`scripts.js:1385, 1414-1415,
1463-1464, 1502, 1508, 1519`, сверено 2026-08-07) — все внутри обработчиков, которые после
разделения переезжают в `loadAiConnectTab()` целиком (сохранение ключа/OAuth физически
происходит только там). Каждое из 7 мест меняет `orSettings` (новый ключ, обновлённый OAuth-статус
и т.п.) — это состояние **читают обе** вкладки, значит сброс должен инвалидировать обе:

```js
function _resetAiSettingsCache() {
  _aiConnectLoaded  = false;
  _aiFeaturesLoaded = false;
}
```

Все 7 точек `_aiSettingsLoaded = false` → `_resetAiSettingsCache()`. Последующий
`setTimeout(loadAiSettings, …)`/прямой вызов `loadAiSettings()` (тот же список строк) →
`setTimeout(loadAiConnectTab, …)`/`loadAiConnectTab()` — перезагружаем **видимую** вкладку
(пользователь только что сохранил ключ ИМЕННО там); «Назначение генераций» получит свежие
данные лениво, при следующем клике по ней (флаг уже сброшен `_resetAiSettingsCache()`) — не
нужно принудительно дозагружать невидимую вкладку.

### Тест-план
- Открыть «Подключение AI» первым (не «Назначение генераций») → рендерится корректно, без
  ошибки о ненайденном `_disciplinesCache`-подобном стейте (независимость подтверждена).
- Открыть «Назначение генераций» первым (без захода в «Подключение AI») → тоже рендерится
  корректно с актуальным `orSettings`/`orModels`.
- Сохранить OpenRouter-ключ на «Подключение AI» → статус обновляется на этой же вкладке;
  переключиться на «Назначение генераций» → карточки отражают новый статус ключа (не
  закешированный старый — регресс на `_resetAiSettingsCache()`).
- Deep-link с дашборда (предупреждение о неконфигурированном провайдере) ведёт на
  «Подключение AI», не на несуществующий `data-tab="ai-settings"`.

   аналог, чтобы прижать блок к правому краю `.page-header` — соблюсти

   **свериться при реализации**); `.ais-restart-btn`/`.ais-status` — существующие классы,
   переиспользуются как есть, стили не трогаем.
3. Обработчик (`scripts.js:1359-1397`, сверено 2026-08-07 — весь блок
   `document.getElementById('ais-restart-btn').addEventListener('click', ...)`) — переносится
   из тела `loadAiConnectTab()`/бывшего `loadAiSettings()` в **глобальную инициализацию**
   `scripts.js` (тот же уровень вложенности, что строка `883`

   скрипта, не при первом открытии вкладки). Внутреннее содержимое обработчика (`POST
   /api/restart` + поллинг `/api/auth-status`, до 20с) — **без изменений**; финальная строка

   `_resetAiSettingsCache(); if (document.getElementById('tab-ai-connect')?.classList.contains('active')) loadAiConnectTab(); if (document.getElementById('tab-ai-features')?.classList.contains('active')) loadAiFeaturesTab();`
   — после переноса кнопки перезапуск может случиться с ЛЮБОЙ открытой вкладкой страницы
   «Инструменты», не только «Подключение AI» — перезагружать нужно ту (или те — в моменте
   активна ровно одна), что сейчас видна, если это одна из двух AI-вкладок; если открыта
   «Учёт данных»/«Инструкции» — сброс кеша всё равно происходит, обе AI-вкладки перезагрузятся
   лениво при следующем открытии.

### Тест-план
- Кнопка «⟳ Перезапустить сервер» видна на странице «Инструменты» **сразу**, при любой
  открытой вкладке (включая «Учёт данных», «Инструкции» — не только AI-вкладки) — регресс на
  прежнее поведение, где кнопка появлялась только после первого захода на «Модели AI».
- Клик по кнопке при открытой «Учёт данных» → сервер перезапускается, статус-текст обновляется
  в `.page-header`, AI-вкладки (если их потом открыть) показывают актуальные данные без
  собственной перезагрузки страницы браузера.
- Клик по кнопке при открытой «Подключение AI» → та же вкладка перечитывает `.env`
  автоматически после рестарта (сохранённое поведение, не регресс).

## Порядок реализации

Зависимости между пунктами:
1. **П.1 (остаток) + П.3-Б** — один PR (П.3-Б определяет новую вкладку по умолчанию, на
   которую переключается П.1 после удаления «Модуль») — без зависимости от П.4-П.6.
2. **П.6 → П.4 → П.5** — строго в этом порядке: П.6 выносит кнопку рестарта из
   `.ais-restart-section` ДО того, как П.4 разбивает окружающую разметку на две функции (проще
   вырезать секцию один раз из ещё цельной `loadAiSettings()`, чем синхронизировать вырезание
   с одновременным split); П.5 — чисто визуальная доводка после того, как П.4 физически развёл
   панели.

Каждый пункт — самостоятельный коммит, кроме П.1+П.3-Б (одна логическая правка одного и того
же тег-бара) и П.6+П.4 (П.6 без П.4 оставляет `.ais-restart-section` вырезанной из «сиротской»
функции на полпути — короткое несогласованное состояние внутри одной ветки работы, не
отдельные PR).
