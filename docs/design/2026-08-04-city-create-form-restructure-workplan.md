# План: реструктуризация формы «Создать новый домен»

**Дата:** 2026-08-04 · **Роль:** Аналитик · **Статус:** план, к реализации не приступали

## Контекст задачи

Форма создания города (`web/public/index.html`, `#city-create-spoiler`) сейчас
показывает при создании все структурные секции сеттинга наравне — включая те,
для заполнения которых на этапе создания обычно ещё нет материала (расклад
сил, география, ключевые точки). Задача — сократить форму создания до
действительно нужного на старте, оставив остальное доступным через просмотр
и редактирование уже созданного города.

Разбор кода (`web/lib/parsers/city.js` — `CITY_SECTIONS`/`cityScaffold`;
`web/public/scripts/city.js` — `CITY_SECTION_DEFS`/`CITY_RULE_SECTIONS`/
`_renderCityView`/`_renderCityEdit`; `web/public/scripts/scripts.js` —
обработчик `#btn-new-city`; `web/public/index.html` — разметка формы) даёт
следующую картину «что есть сейчас»:

| Секция city.md | Ключ | Форма создания сейчас | Форма редактирования сейчас | Просмотр сейчас |
|---|---|---|---|---|
| Политический ландшафт | `political` | видна, обязательного вида | структурный редактор (`_cityPolEditorHtml`) | сырой markdown (весь `body`) |
| Районы | `districts` | видна («География»), карточки районов, создаёт папки при сборке города | карточки районов (`_cityDistrictsEditEditorHtml`) | карточки районов (`_cityViewDistrictsHtml`) |
| Ключевые локации | `locations` | видна, под меткой **«Значимые места города»** (см. риск №2 ниже) | структурный редактор (`_cityLocEditorHtml`) | сырой markdown |
| Значимые места | `landmarks` | внутри свёрнутого «Правила и ограничения» | плоский textarea вперемешку со всеми остальными | сырой markdown |
| Лейтмотивы/Специфика/Избегать/Источники | `leitmotif`/`specifics`/`avoid`/`sources` | 4 отдельных `.form-group` без общего заголовка | то же, плоско | сырой markdown |
| Охотничьи угодья, Законы, Смертные институции, Календарь, Технологии, Ограничения, Именник | `hunting`/`edicts`/`mortals`/`calendar`/`tech`/`limits`/`naming` | сгруппированы в свёрнутый `#city-create-rules` («Правила и ограничения города», необязательно) | плоско, вперемешку со всеми секциями | сырой markdown |

Важно: карточки районов (POST/PUT/DELETE `/api/cities/:slug/districts`) —
уже готовая, полностью самостоятельная функциональность из прошлого цикла
(§A3–A5). Это значит, что «спрятать раздел из формы создания» для districts
не теряет возможностей — район всё равно можно добавить сразу после
создания города тем же UI, просто на один экран позже.

## Задачи

### T1 · 🔴 Скрыть «Политический ландшафт» из формы создания
Убрать блок `.city-create-section-label` «Политический ландшафт» +
`#city-political-editor` из `#city-create-spoiler`. Поле `political`
в `POST /api/cities` как было необязательным (пустая секция уже сегодня
пишется как `- …`), так и останется — просто перестаёт быть частью payload
формы создания. Доступ — только через `_renderCityEdit`/`_renderCityView`
(там уже есть, без изменений).

**Риск:** нет. Ничего не блокирует.

### T2 · 🔴 Скрыть «География» (районы) из формы создания
Убрать блок `.city-create-section-label` «География» + `#city-districts-editor`
из `#city-create-spoiler`. Обработчик `#btn-new-city` (`scripts.js`) уже
использует `_cityDistrictsCreateHost ? … : []` — при отсутствии узла в DOM
код деградирует сам, без правки логики сбора payload.

**Открытый вопрос (см. риск №1):** пользователь теряет пакетное создание
N районов одним действием при создании города — район придётся добавлять
по одному сразу после (через уже существующие карточки на странице города).
Нужно подтверждение, что это ожидаемый компромисс.

### T3 · 🟡 Выделить «Лейтмотивы и атмосфера / Специфика ответа / Чего избегать / Источники» в отдельный раздел
Сейчас — 4 разрозненных `.form-group` без общего заголовка, посреди формы.
Обернуть в поименованный блок (по образцу `.city-create-section-label`
«Политический ландшафт»/«География») — например «Голос и стиль хроники» —
чтобы визуально отделить нарративные настройки от структурных данных
сеттинга.

**Решение по умолчанию:** держать блок **не свёрнутым** (в отличие от
«Правила и ограничения») — это голос Рассказчика с первой сцены, не
опциональный мелкий тюнинг. Свернуть в `<details>` только если пользователь
явно попросит.

### T4 · 🔴 Скрыть «Ключевые локации» и «Значимые места» из формы создания
- `locations` («Ключевые локации») — убрать блок целиком (сейчас висит под
  ошибочной меткой «Значимые места города», см. риск №2 — блок убирается,
  метка-баг снимается заодно).
- `landmarks` («Значимые места») — убрать из `CITY_RULE_SECTIONS`
  **только для формы создания**; в форме редактирования/просмотра (T5) эта
  секция должна остаться в группе «Правила и ограничения».

**Технический нюанс:** `CITY_RULE_SECTIONS` в `city.js` сейчас — общий
константный список для рендера свёрнутого блока формы создания и для сбора
payload (`scripts.js`, через `document.getElementById('city-' + key)`).
Если после T5 тот же компонент рендера начнёт использоваться и в форме
редактирования, но с landmarks, а форма создания — без, нужен **общий базовый
список + один флаг/фильтр исключения**, а не два независимых литерала
(иначе через полгода списки разойдутся — тот же класс проблемы, который в
прошлом цикле уже правили для `CITY_SECTIONS`).

### T5 · 🟡 Добавить раздел «Правила и ограничения города» в просмотр и редактирование
- **Просмотр (`_renderCityView`)** — де-факто уже показывает все `##`-секции
  как единый markdown (`mdToHtmlBlock(body)`), включая все 7–8 полей правил.
  Формально «отображается» уже сегодня. Рекомендация: считать пункт
  выполненным для просмотра без правок кода; визуальное выделение в отдельную
  панель — необязательный косметический довесок, не блокирующий остальное.
- **Редактирование (`_renderCityEdit`)** — реальная правка нужна: сейчас эти
  8 ключей рендерятся плоским циклом `CITY_SECTION_DEFS.map(...)` вперемешку
  со всеми остальными полями, визуальной группировки нет вообще (хуже, чем в
  форме создания, где они хотя бы в одном `<details>`). Нужно вынести их из
  общего цикла и отрендерить тем же (адаптированным под T4) компонентом,
  что и в форме создания — с тем же заголовком «Правила и ограничения
  города», предзаполненным текущими значениями секции.

**Зависимость:** делать после/вместе с T4 — обе задачи трогают
`CITY_RULE_SECTIONS`, лучше одним заходом, чтобы не расходились.

## Порядок реализации

Независимые друг от друга: **T1, T2, T3** — чистая перекладка разметки
формы создания, без пересечений.

Связка **T4 → T5** — общий рефакторинг `CITY_RULE_SECTIONS` в
«базовый список + исключение для формы создания», выполнять последовательно
одним циклом правок.

## Риски и открытые вопросы (нужно подтверждение перед реализацией)

1. **T2 — потеря пакетного создания районов.** После скрытия «Географии» из
   формы создания район добавляется только постфактум, по одному, через уже
   готовый UI карточек на странице города. Функциональность не теряется,
   удобство пакетного ввода — да. Подтвердить, что это приемлемо.
2. **Термин «Отмеченные локации».** В коде такого заголовка нет — трактую
   как секцию `landmarks` («Значимые места»), по смыслу совпадающую с
   «отмеченные, знаковые точки города». Если имелось в виду что-то другое —
   поправить до начала реализации.
3. **Побочно найденный баг разметки.** В текущей форме создания секция
   `#city-locations-editor` (данные `locations`/«Ключевые локации») подписана
   меткой «Значимые места города» — не совпадает ни с одним из канонических
   заголовков `CITY_SECTIONS`. T4 снимает вопрос для формы создания (блок
   убирается целиком); в форме редактирования такого рассогласования нет —
   там подписи идут напрямую из `CITY_SECTION_DEFS`/`CITY_FIELD_TIPS`.
