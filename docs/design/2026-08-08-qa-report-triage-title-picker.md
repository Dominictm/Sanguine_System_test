## 1. 🔴 `_charTimelineDigest` не видит новый лейбл «Титул в городе»

### 1.1 Точная причина (подтверждена дословным репро в отчёте QA)

**Файл:** `web/routes/modules/shared.js:245`, функция `_charTimelineDigest(name, kind, card)`
(строки 241-259) — строит компактный дайджест персонажа для AI-промта при заполнении модуля
(`routes/modules/fill.js:63`, `charDigests.push(_charTimelineDigest(...))`).

```js
const hier = field(/\*\*Парижская иерархия:\*\*\s*([^\n]+)/) || field(/\*\*Иерархия в городе:\*\*\s*([^\n]+)/);
```

A2 (2026-08-07) переименовал канонический лейбл карточки персонажа с «Иерархия в городе» на
«Титул в городе» (`EDITABLE_FIELD_MAP.hierarchy`, `web/lib/db.js:528`) и обновил парсер
(`web/lib/parsers/character.js:138`, добавлено точное совпадение на новый лейбл рядом со
старым regex-фоллбэком). Эта функция парсит карточку САМОСТОЯТЕЛЬНО, собственным регэкспом
(не через `parseCharacter()`) — про новый лейбл её не предупредили, она осталась жить в другом
модуле (`routes/modules/`), вне зоны, которую A2 трогала напрямую.

**Наблюдаемое поведение** (эмпирически воспроизведено QA):
```
card = '- **Титул в городе:** Шериф'
hier extracted: "" (ожидалось "Шериф")
```
Для всех 29 мигрированных персонажей и любых новых карточек строка дайджеста
`- Роль/иерархия: ...` молча теряет титул/должность — AI при заполнении модуля перестаёт
видеть, что персонаж Шериф/Примоген/Князь, без единой ошибки в логах. `_charTimelineDigest` не
упомянута в `all.test.js` ни разу — `npm test` (712/712) эту находку в принципе не мог поймать.

### 1.2 Контракт исправления

```js
// было:
const hier    = field(/\*\*Парижская иерархия:\*\*\s*([^\n]+)/) || field(/\*\*Иерархия в городе:\*\*\s*([^\n]+)/);
// стало (тот же порядок фоллбэка, что уже установлен в character.js:138 — новый лейбл первым,
// оба легаси-варианта следом, ничего не убираем):
const hier    = field(/\*\*Титул в городе:\*\*\s*([^\n]+)/) || field(/\*\*Парижская иерархия:\*\*\s*([^\n]+)/) || field(/\*\*Иерархия в городе:\*\*\s*([^\n]+)/);
```

**Почему не переводить функцию на `parseCharacter()`** (рассмотрено и отклонено): функция и так
не пользуется общим парсером ни для одного из своих пяти полей (Статус/Детали статуса/Роль/Год
обращения/Отношения — все читаются собственными regex) — это существующий паттерн файла, не
изъян, привнесённый A2. Переход на `parseCharacter()` для одного поля создал бы несогласованность
внутри той же функции и потребовал бы понять, принимает ли `parseCharacter()` сырой текст
карточки или слаг/путь (сигнатуру не проверял — вне объёма точечного фикса). Симметричный
regex-фоллбэк, зеркалящий уже принятое решение в `character.js:138`, — минимальный по риску путь.

### Тест-план
- `_charTimelineDigest('Х', 'ПК', '- **Титул в городе:** Шериф')` → строка результата содержит
  `Роль/иерархия: Шериф`.
- Легаси-карточка `- **Иерархия в городе:** Примоген` (немигрированная гипотетически, или
  сохранённая до прогона миграции 007) → всё ещё матчится (регресс-тест на фоллбэк).
- Карточка только с `- **Парижская иерархия:** Неофит капеллы` (случай
  `emiliya_indra_landorg.md`, см. техспеку A2 §2.1) → всё ещё матчится.
- Карточка вообще без поля титула/иерархии, но с `- **Роль:** Гуль» → строка
  `Роль/иерархия: Гуль` (не пропадает целиком — регресс на `if (hier || role)`).
- Живой прогон: `POST /api/chronicles/:chr/modules/:mod/fill` (или эквивалент из `fill.js`) на
  модуле с участником, использующим новый лейбл → в собранном `charDigests` есть строка титула.

## 2. 🟡 Пикер титулов — пустой результат поиска без сообщения

### 2.1 Причина

`web/public/scripts/char-detail.js:1278` (`_renderTitlePickerLists`):
```js
if (allList) {
  allList.innerHTML = rest.length ? rest.map(_titleItemHtml).join('')
    : (all.length ? '' : '<div class="cdet-empty">Библиотека титулов пуста — можно ввести название вручную.</div>');
}
```
Ветка «библиотека вообще пуста» (`all.length === 0`) обработана. Ветка «поиск ничего не нашёл»
(`rest.length === 0`, но `all.length > 0`) — нет: просто пустая строка, список визуально исчезает
без объяснения. QA подтвердил живьём (`zzzNoSuchTitleXYZ` → `allListHTML: ""`).

### 2.2 Контракт исправления

```js
if (allList) {
  allList.innerHTML = rest.length ? rest.map(_titleItemHtml).join('')
    : (all.length
        ? '<div class="cdet-empty">Ничего не найдено — можно ввести название вручную.</div>'
        : '<div class="cdet-empty">Библиотека титулов пуста — можно ввести название вручную.</div>');
}
```
Также стоит проверить `priorityList` тем же способом: если `priority.length === 0` при
непустом query — группа сейчас просто скрывается (`priorityGroup.style.display = 'none'`), что
корректно (заголовок «По вашей секте/клану» над пустым местом не нужен, в отличие от «Все
титулы», которая всегда видна как основной список) — здесь фикс не нужен, только у
`allList`.

### Тест-план
- Открыть пикер, ввести заведомо несуществующее название → видно «Ничего не найдено — можно
  ввести название вручную.», не пустая панель.
- Очистить поиск → сообщение пропадает, список восстанавливается.
- Пустая библиотека (гипотетически) — старое сообщение всё ещё показывается (регресс-тест).

## 3. 🟡 Устаревшая терминология «Иерархия» в user-facing текстах `cities.js`

### 3.1 Причина

Три warning-сообщения (`web/routes/cities.js:282, 294, 303`) — часть
`syncPoliticalCharacterHierarchy` (город → персонаж синк ролей из «Карты фракций»), попадают в
ответ API как `warnings[]` и потенциально показываются пользователю тостом при сбое синка одной
из ролей. Называют поле «Иерархию», хотя в UI (после A2) оно всюду «Титул».

**Не трогаем** три чисто внутренних комментария (строки 150, 269, 456) — не видны пользователю,
переименование ради переименования, риск нулевой пользы.

### 3.2 Контракт исправления

```js
// :282, было:
catch (e) { warnings.push(`Не удалось прочитать персонажей города для синка «Иерархии»: ${e.message}`); return warnings; }
// стало:
catch (e) { warnings.push(`Не удалось прочитать персонажей города для синка «Титула»: ${e.message}`); return warnings; }

// :294, было:
catch (e) { warnings.push(`Не удалось очистить «Иерархию» у «${name}»: ${e.message}`); }
// стало:
catch (e) { warnings.push(`Не удалось очистить «Титул» у «${name}»: ${e.message}`); }

// :303, было:
catch (e) { warnings.push(`Не удалось записать «Иерархию» «${name}» (${role}): ${e.message}`); }
// стало:
catch (e) { warnings.push(`Не удалось записать «Титул» «${name}» (${role}): ${e.message}`); }
```

**Риск:** нулевой — чисто текстовая правка в `catch`-ветках, которые срабатывают только при
реальном сбое записи (сеть/диск), не меняет логику или условия срабатывания.

### Тест-план
Отдельного теста не требует — `grep` по `all.test.js` на точный текст warning-сообщений
(проверить перед коммитом, что ни один существующий тест не ассертит старую формулировку
дословно; если ассертит — обновить синхронно с этой правкой, не отдельным PR).
