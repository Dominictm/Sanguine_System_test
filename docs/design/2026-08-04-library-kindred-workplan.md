# План: удаление/редактирование в Библиотеке + новая вкладка «Сородичи»

**Дата:** 2026-08-04 · **Роль:** Аналитик · **Статус:** план, к реализации не приступали

## Контекст — что уже есть (важно, меняет объём задачи)

Разбор кода показал: пункты 1 и 2 запроса **не с нуля** — в «Библиотеке» уже
есть полноценный CRUD, но **только для «авторских» записей** (созданных
пользователем через «+ Добавить…», помечены `**Авторское:** да` в MD /
`custom: true` в JSON). Канонические записи (`animalism.md` и т.п.) на
бэкенде **защищены**: `PUT`/`DELETE` для них уже возвращают 403
(`web/routes/library.js`, комментарий «Фаза I», строки ~188–193). Мягкое
удаление — файл уезжает в `_deleted/<slug>_<таймстамп>/`, не стирается
безвозвратно. Этот же паттерн (custom-only запись, soft-delete, шаблон
слага) — готовый прецедент, который новые категории «Кланы»/«Секты» могут
скопировать один в один, не изобретая CRUD заново.

**Но** сегодняшний UX не совпадает с тем, что описано в запросе:

| Сегодня | Просят |
|---|---|
| Клик по карточке → открывается **отдельная read-only** модалка (только просмотр, без Edit/Delete) | Клик по карточке → модалка с кнопками **Редактировать**/**Удалить** в шапке |
| Edit/Delete — **отдельные** карандаш/корзина-иконки прямо на карточке (видны только у авторских записей), открывают **третью**, отдельную форму-модалку | Кнопка «Редактировать» переключает **саму** открытую модалку в режим правки |
| Закрытие модалки — без проверки на несохранённые правки | Клик мимо/закрытие в режиме правки должно спросить про сохранение |

То есть пункты 1–2 — не «добавить функционал», а **объединить три
существующих экрана в один** (просмотр + правка + удаление в одной
модалке) и добавить недостающее (dirty-check при закрытии — такого нигде
в проекте пока нет вообще, ближайший прецедент — `_v20DirtyFlag` в
`v20-sheet.js`, но там это гейт на другое действие, не диалог при закрытии).

## Задачи

### K1 · 🔴 Единая модалка карточки библиотеки (просмотр + правка + удаление)
Новый общий компонент взамен связки «read-only модалка + отдельная форма
редактирования + отдельная форма удаления»:
- Шапка: название + кнопка **✏ Редактировать** (переключается на
  **✓ Сохранить** в режиме правки) + кнопка **🗑 Удалить**.
- Режим правки — все секции карточки (не только «шапочные» поля вроде
  названия/источника, но и все «Уровень N» блоки) становятся полями ввода.
  Прецедент множественных независимых per-секция edit/save/cancel уже есть
  (`editPanel()` в `locations.js`) — здесь нужен **один общий** переключатель
  на всю модалку, не по секции, ближе к паттерну шапки персонажа
  (`#cdet-edit-btn`/`#cdet-delete-btn` в `char-detail.js`), но
  распространённый на все секции сразу, а не только на «Информацию».
- 🗑 Удалить → `showConfirm()` (уже готовая функция,
  `web/public/scripts/utils.js:52`, `Promise<boolean>`) с текстом
  предупреждения — не собственный велосипед диалога.
- Закрытие (крестик/клик мимо) при несохранённых правках → тот же
  `showConfirm()` с вопросом «Сохранить изменения?» — **новая** логика,
  прецедента в проекте нет, реализуется как обёртка вокруг закрытия модалки
  на dirty-флаге.

**Решено:** защита сохраняется — Редактировать/Удалить в шапке доступны
**только для авторских записей**, как сегодня. Канонические статьи
(дисциплины/кланы/секты из справочника) остаются курируемым, сверенным с
правилами контентом, не редактируемым через UI. Точный вид шапки для
канона (скрыть кнопки полностью или показать задизейбленными с подсказкой)
— решается на этапе дизайнера, не блокирует техспеку.

### K6 · 🟢 Наполнение контентом (Кланы + Секты)
- **Источник кланов** — wod.su/vampire/clans: индекс-страница, реально
  сгруппирована по принадлежности — **Камарилья** (10 кланов: Бруха,
  Вентру, Гангрел, Горгульи, Каитиффы, Малкавианы, Носферату, Ласомбра-
  отступники, Тремер, Тореадор), **Шабаш** (Ласомбра, Цимисхи и ~15
  вариантов-«отступников»/антитрайб + Пандеры/Предвестники Черепов),
  **Независимые** (Ассамиты, Баали, Джованни, Каппадокийцы, Последователи
  Сета, Равнос, Салюбри, Самеди и др. — всего 13). Каждый клан — отдельная
  подстраница на wod.su (карточка сама по себе не содержит текста, только
  ссылку) — контент по каждому клану собирается со страницы клана
  отдельно, не с этой индекс-страницы.
- **Источник сект** — wod.su/vampire/sects: 7 записей (Камарилья, Шабаш,
  Анархи, Независимые, Инконню, Инферналисты, Истинная Чёрная Рука), у
  каждой есть краткое описание прямо на индекс-странице + ссылки на
  детальные подстраницы.
- **wod.fandom.com — доступ найден.** Штатный инструмент чтения веб-страниц
  (WebFetch) возвращал `402` на обеих ссылках категорий — это ограничение
  именно того инструмента/прокси, не блокировка самим fandom.com: прямой
  `curl` (через Bash, с обычным `User-Agent` браузера) отдаёт обе страницы
  полностью (`200`, ~270–370 КБ HTML). Проверено на обеих ссылках из
  запроса — категория «Кланы» и категория «Секты кланов» читаются штатно.
  Для наполнения (K6) страницы кланов/сект тем же способом (`curl` + разбор
  HTML) — рабочий, проверенный путь, доп. согласований не требует.
  Попутно подтверждён и масштаб: категория «Кланы» на fandom.com — это не
  ~30 записей, как на wod.su, а **174** (клановые статьи + все секто-
  варианты типа «Бруха (Шабаш)», «Ассамиты (Визири)» и т.п. + бладлайны
  вроде Волгирре/Ву Зао/Геката) — ещё одно подтверждение, что наполнять
  всё сразу нецелесообразно (см. ниже).
- **Наполнение — «своими словами», не копипаста.** Уже установленная в
  проекте конвенция (`psychics/README.md`: «текст — добросовестный
  пересказ своими словами, не копипаста») — переносится и на кланы/секты.
- **Решено — объём этого цикла:** только 🔴 7 «базовых» кланов корбука V20
  (Бруха, Вентру, Гангрел, Малкавиан, Носферату, Тореадор, Тремер) + все
  7 сект (Камарилья, Анархи, Шабаш, Независимые, Инконню, Инферналисты,
  Истинная Чёрная Рука). Наполняются по конвенции проекта — своими
  словами, не копипаста, ссылка на источник в поле «Источник».

  **⏸️ ОТЛОЖЕНО (не в этом цикле, отметка для будущего запроса):**
  - остальные кланы Камарильи/Независимых из corebook V20 (Ассамиты,
    Джованни, Равнос, Последователи Сета, Каппадокийцы, Салюбри и др. —
    ~13 записей на wod.su);
  - Шабаш-«отступники»/антитрайб-варианты (~15 записей на wod.su);
  - сект-варианты кланов и бладлайны с wod.fandom.com (Бруха (Шабаш),
    Ассамиты (Визири), Волгирре, Ву Зао, Геката и т.д. — до 174 записей
    категории «Кланы» на fandom.com, см. ниже про масштаб).
  Расширение до этого объёма — отдельный запрос, когда понадобится;
  схема данных (K3/K4) проектируется так, чтобы добавление новых записей
  позже было просто «ещё один MD-файл», без правок парсера/бэкенда.

## Порядок реализации

1. **K1** — блокирует K2 и K5, делать первой.
2. **K2** и **K3/K4** — независимы друг от друга, можно параллельно после K1.
3. **K5** — после K1 (модалка) и K3+K4 (данные/бэкенд, иначе нечем
   наполнять карточки).
4. **K6** — можно начинать параллельно с K3/K4 (наполнение конкретных MD-
   файлов не блокирует парсер/роуты), но по факту наполнение имеет смысл
   только после того, как K3/K4 зафиксируют точную схему полей карточки.

## Решения, зафиксированные пользователем

1. **Доступ к правке канона** (K1) — защита сохраняется: править/удалять
   можно только авторские записи, как сегодня.
2. **Доступ к wod.fandom.com** (K6) — найден: прямой `curl` (Bash) читает
   обе страницы категорий полностью, `WebFetch` тут не годится (`402`
   именно у него), но это не блокер задачи.
3. **Объём наполнения** (K6) — только 7 базовых кланов + 7 сект в этом
   цикле; всё остальное (кланы Sabbat-антитрайб, независимые сверх
   базовых, сект-варианты/бладлайны с fandom.com) — отмечено выше как
   ⏸️ ОТЛОЖЕНО, отдельным запросом когда понадобится.

Открытых вопросов не осталось — план готов к передаче системному
аналитику.
