## 1. Кнопка-триггер пикера титулов (A2.8)

### 1.1 Где физически размещать

Поле «Титул» живёт в сетке `.cdet-fields` (`grid-template-columns: auto 1fr`,
`styles.css:3555-3559`) — левая колонка `.cdet-key` (лейбл), правая `.cdet-val`
(значение/инпут). В режиме редактирования `.cdet-val` уже содержит один
`<input class="cdet-field-input">` на всю ширину правой колонки. Кнопка
пикера — **не отдельная колонка сетки** (не ломать 2-колоночную структуру
ради одного поля из ~15) — вместо этого правая ячейка для `hierarchy`
конкретно становится flex-контейнером `input + button` внутри той же
`.cdet-val`:

```html
<div class="cdet-val" data-field="hierarchy">
  <div class="cdet-field-with-pick">
    <input class="cdet-field-input" data-field="hierarchy" ...>
    <button type="button" class="cdet-lib-pick-btn" data-pick-title="1"
            title="Выбрать титул из библиотеки" aria-label="Выбрать титул из библиотеки">📚</button>
  </div>
</div>
```

```css
.cdet-field-with-pick { display: flex; gap: 6px; align-items: center; }
.cdet-field-with-pick .cdet-field-input { flex: 1; min-width: 0; }
.cdet-lib-pick-btn {
  flex-shrink: 0;
  width: 32px; height: 32px;
  display: inline-flex; align-items: center; justify-content: center;
  background: var(--bg2);
  border: 1px solid var(--border);
  border-radius: var(--r-md);
  color: var(--text2);
  cursor: pointer;
  font-size: var(--fs-lg);
}
.cdet-lib-pick-btn:hover { border-color: var(--gold); color: var(--gold); }
@media (pointer: coarse) { .cdet-lib-pick-btn { width: 44px; height: 44px; } }
```

Иконка 📚 (эмодзи, не svg-спрайт) — консистентно с остальным проектом:
эмодзи-иконки уже повсеместны в этом интерфейсе (📖 дневники, 🖼️ изображения,
✕/🗑 удаление) — свой набор svg-иконок в проект не заводился нигде, вводить
его ради одной кнопки не нужно.

Touch-target 44px на `pointer: coarse` — по правилу проекта (`CLAUDE.md`,
«Touch-цели ≥44px») — 32px базовый размер (десктоп, мышь) достаточен визуально
рядом с полем ввода стандартной высоты, но обязательно расширяется на тач.

### 1.2 Расширяемая панель, а не модалка поверх модалки

Техспека оставляет открытым, как рендерить сам список — «рендер модалки»
только в комментарии псевдокода. **Дизайнерское решение: не модалка.**

Причины:
- В проекте уже есть ровно этот паттерн — `.v20-lib-picker`
  (`v20-sheet.js:1731-1758`, `styles.css:9422`, сверено 2026-08-07 — было `:9311-9364`) для дисциплин/нумины/
  бэкграундов/достоинств-недостатков в V20-листе: раскрывающаяся встроенная
  панель под полем, а не отдельное модальное окно. Он уже решил ту же задачу
  («выбрать одно из библиотечного списка внутри формы»).
- Персонажный модал (`#char-detail-modal`) уже открыт, когда пользователь
  жмёт кнопку — открытие ВТОРОГО модального окна поверх первого means
  вложенные оверлеи, конкурирующий фокус-трап, необходимость явно управлять
  z-index сверх `--z-modal` (семантическая шкала z-index — dropdown → sticky
  → modal-backdrop → modal → toast → tooltip — не предусматривает «modal
  поверх modal» как штатный уровень). Раскрывающаяся панель избегает всего
  этого класса рисков целиком, не требуя новой ступени в шкале.
- Список титулов — потенциально ~100 записей (после наполнения данными,
  уже выполненного в этой сессии) — `max-height: 200px; overflow-y: auto`
  у `.v20-lib-list` уже решает проблему длины списка проверенным способом.

**Разметка** (переиспользует классы `.v20-lib-picker`/`.v20-lib-list`/
`.v20-lib-item`/`.v20-lib-hint` — они не завязаны на V20-лист семантически,
только на класс имени; переносимы в контекст `char-detail.js` как есть, без
дублирования CSS):

```html
<div class="v20-lib-picker" id="cdet-title-picker" hidden>
  <input class="v20-lib-search" placeholder="Поиск по названию…" id="cdet-title-search">
  <div class="cdet-title-picker-group" data-group="priority">
    <div class="cdet-title-picker-group-label">По вашей секте/клану</div>
    <div class="v20-lib-list" id="cdet-title-list-priority"></div>
  </div>
  <div class="cdet-title-picker-group" data-group="all">
    <div class="cdet-title-picker-group-label">Все титулы</div>
    <div class="v20-lib-list" id="cdet-title-list-all"></div>
  </div>
</div>
```

```css
.cdet-title-picker-group + .cdet-title-picker-group { margin-top: 10px; }
.cdet-title-picker-group-label {
  font-family: var(--f-heading);
  font-size: var(--fs-2xs);
  letter-spacing: .1em;
  text-transform: uppercase;
  color: var(--text3);
  margin-bottom: 4px;
}
```

**Один `.v20-lib-item` на титул**, `.v20-lib-hint` — вторая строка серым,
показывает `affiliation` (уже есть паттерн — bg. `background`-пикер кладёт
туда `category`/`sectOnly`, здесь по аналогии кладём `t.affiliation`):
`Приск — Ассамиты · клан`. Если у титула есть флаг «Негативный» — префикс
`⚠️ ` перед именем в `.v20-lib-item` (тот же смысловой сигнал, что бейдж
`.lib-card-negative-badge` в самой библиотеке, но без заведения ещё одного
CSS-класса ради инлайн-списка — достаточно текстового маркера в контексте
компактного списка).

**Группа «По вашей секте/клану» скрывается целиком**, если пуста (Секта/Клан
персонажа ещё не заполнены, или совпадений нет) — не показывать пустой
заголовок-сироту. Поиск (`#cdet-title-search`) фильтрует обе группы разом
(тот же принцип, что и обычный `.v20-lib-search`, если он используется для
поиска в существующих пикерах — **проверить при реализации**, использует ли
текущий `.v20-lib-search` живой фильтр по вводу или это просто визуальный
инпут без логики; если фильтра нет — завести per спецификации, поиск по
100 записям без него неудобен).

**Пустая библиотека** (edge case, актуален был до наполнения данными в этой
сессии — на будущее, если у пользователя когда-то будет пустая вкладка
«Титулы»): `.v20-lib-list` пуст → показать `<div class="cdet-empty">Библиотека
титулов пуста — можно ввести название вручную.</div>` вместо пустого списка
(переиспользует `.cdet-empty`, уже применяется в этом же модальном окне для
пустых дневников/фамильяра — `char-detail.js`).

### 1.3 Взаимодействие

Клик по кнопке 📚 → тоггл `hidden` на панели (открыта/закрыта), как
`_v20ToggleLibPicker`. Клик по `.v20-lib-item` → подставляет `t.name` в
поле `input[data-field="hierarchy"]`, закрывает панель, **фокус возвращается
в инпут** (не теряется на кнопке) — пользователь может сразу donisправить
вручную (например, добавить уточнение к названию). Ручной ввод в поле не
блокируется в любой момент — кнопка лишь ускоряет, не заменяет прямой ввод.

## 2. Даталисты Клан/Секта/Дисциплины (A3)

Нативный `<datalist>` — браузер рисует подсказки сам, вне контроля CSS
проекта (`::-webkit-calendar-picker-indicator`-уровня хаков не заводим).
**Дизайнерского решения не требуется** — это осознанный выбор «встроенный
минимализм вместо кастомного виджета» (см. техспеку A3.2 и решение
пользователя §0.2), поле выглядит как обычный текстовый инпут без визуальных
отличий от остальных полей вкладки «Информация». Единственная точка
внимания: **не добавлять кнопку-иконку** рядом с этими тремя полями (в
отличие от «Титул» из §1) — так проект визуально различает «поле с активным
UI-виджетом выбора» (кнопка) от «поле с пассивной подсказкой браузера»
(без кнопки), не создавая ложного ожидания у Клан/Секта/Дисциплины, что
там есть что-то большее, чем автодополнение.

## 3. Тултипы (B1, B2)

**Ноль новых визуальных решений.** `.field-tip`/`.field-tip-popup` — готовый,
неоднократно применённый и специально допиленный компонент (см. комментарий
в `styles.css:2444-2455` — уже прошёл через фикс бага с позиционированием
поверх нативных `<input>`/`<select>`, использовать как есть). Задача B1/B2 —
чисто контентная (тексты подсказок) и точки подключения (`fieldTip(...)` в
разметке), не требует дизайнерского участия сверх уже написанного в техспеке.

Единственное, что стоит проверить дизайнерским глазом при реализации — 7 точек
подключения в `locations.js` (B2, было 6 на момент постановки — состав полей вкладки «Контекст
ВТМ» поменялся несвязанной фичей «Статус заменяет Зону», см. обновлённый техспек) не создают
визуального дисбаланса в табличных рядах `.locdet-row`/`.locdet-field-row` (тултип у длинных
лейблов вроде «Постоянные фигуры» — убедиться, что `ⓘ` не переносится на новую строку
отдельно от текста лейбла; `.field-tip { display: inline-flex }` с
`margin-left: 7px` обычно держится в потоке текста, но именно у самых длинных
лейблов стоит визуально свериться на узких экранах). Дополнительно — чекбокс «Частный
домен» (новое поле, отсутствовало на момент постановки) рендерит `fieldTip()` рядом с
`<label class="locdet-checkbox-row">`, не с обычным `.locdet-field-lbl` — свериться, что
`ⓘ` не съезжает вертикально относительно текста чекбокса (другой контекст вёрстки, чем
табличные ряды).

## 4. Вкладка «Фракции» города (C1, C2)

### 4.1 Layout

Точное повторение существующего паттерна «Другие фракции»
(`.cdet-faction-group-label` + `<textarea class="form-control" rows="2">`,
с `fieldTip()` у заголовка) — техспека уже даёт готовую разметку (§C1),
дизайнерски добавить нечего: три текстовых блока подряд (Другие / Фракции
смертных / Государственные), одинаковый визуальный вес, без чипов (в отличие
от «Секты»/«Независимые кланы» выше — те справочники с фиксированным
списком, эти — свободный ввод, как и было решено техспекой).

### 4.2 Единственная дизайнерская правка сверх техспеки

Три подряд идущих одинаковых по виду блока «label + textarea» (Другие /
Смертных / Государственные) визуально сливаются без разделителя — сейчас
между «Секты»/«Независимые кланы»/«Другие фракции» разделителя тоже нет
(они и сейчас идут встык), но раньше это были 2 чип-группы + 1 текстовое
поле — разный визуальный ритм давал естественную паузу глазу. Три текстовых
поля подряд — монотоннее. Рекомендация: небольшой `margin-top: 14px` (вместо
базового `gap` формы) перед «Фракции смертных» и «Государственные фракции»
(не перед «Другие фракции» — та примыкает к чипам, естественная граница уже
есть) — визуально группирует «свободный ввод» тремя блоками, читаемыми по
отдельности, без введения новых бордеров/фонов (изменение спейсинга, не
новый компонент).

```css
.cdet-faction-group-label[data-group="mortal"],
.cdet-faction-group-label[data-group="state"] { margin-top: 14px; }
```
(либо эквивалентно через порядковый селектор `nth-of-type`, если размечать
`data-group` не хочется заводить — деталь реализации, не принципиальна.)

### 4.3 C3 (переименование лейбла) — без визуальных последствий

Чисто текстовая правка («Влияние — Секта» → «Влияние — Фракции»), длина
строки практически не меняется, разметка/стили не затронуты.
