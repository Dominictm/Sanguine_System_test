# План — touch-таргет `.btn-submit` на `pointer: coarse`

> Роль-автор: **Аналитик**. Адресат: **Системный аналитик** (написать техспеку для
> Разработчика на основе этого плана).
> Дата: 2026-08-13. Источник: находка Д-2 из QA-отчёта по вкладке «Бэкап» (роль
> «Тестировщик», этот же диалог) + перепроверка на живом сервере перед тем, как писать
> план — исходная формулировка находки оказалась шире, чем реальный дефект.

---

## Что было заявлено vs что подтвердилось

QA-отчёт зафиксировал: «кнопка "Загрузить бэкап…" и обе кнопки модалки подтверждения
("Отмена"/"Восстановить") — 33px высотой, ниже минимума 44px», и сделал вывод, что
проблема — в двух общих классах: `.btn-submit` и `.chr-modal-btn`.

Перед тем как писать план, перепроверил на живом сервере — исходный замер был получен
через `Emulation.setDeviceMetricsOverride({mobile:true})` **без**
`Emulation.setTouchEmulationEnabled`, из-за чего `pointer: coarse` фактически не
активировался, и измерения снимались в режиме `pointer: fine`. С правильно включённой
touch-эмуляцией (`matchMedia('(pointer: coarse)').matches === true`, подтверждено):

| Кнопка | Класс | Высота на `pointer: coarse` |
|---|---|---|
| «Загрузить бэкап…» | `.btn-submit .bkp-restore-btn` | **33px — подтверждено, дефект реален** |
| «Создать бэкап» | `.btn-submit` | **33px — тот же дефект** |
| «Отмена» (модалка восстановления) | `.chr-modal-btn` | 44px — **уже соответствует**, ложная тревога |
| «Восстановить» (модалка восстановления) | `.chr-modal-btn` | 44px — **уже соответствует**, ложная тревога |

Причина, почему `.chr-modal-btn` в порядке: класс уже входит в существующий общий список
`@media (pointer: coarse) { .btn-icon, .tab-btn, ..., .chr-modal-btn, ... { min-height: 44px; } }`
([`web/public/styles.css:2913-2927`](../../web/public/styles.css#L2913-L2927)).
`.btn-submit` в этот список — и ни в один из 24 остальных `@media (pointer: coarse)`
блоков файла — не входит (проверено `grep` по всем блокам).

**Скорректированный объём: только `.btn-submit`.** Правка `.chr-modal-btn` не нужна.

---

## Масштаб

`.btn-submit` используется в 18 местах `index.html` и ещё в 4 JS-файлах
(`archive.js`, `backup.js`, `log-session.js`, `scripts.js`) — это основной класс
«главной» кнопки действия по всему приложению (не только в «Бэкапе»): «Проверить»,
«Создать домен», «Зафиксировать присутствие», «Закрыть хронику», и т.д.

Это подтверждает решение из предыдущей техспеки — чинить нужно **класс целиком**, не
точечно кнопки вкладки «Бэкап»: 18+ мест уже страдают тем же дефектом, точечный патч
трёх кнопок оставил бы остальные 15 нетронутыми без всякой логики, почему одни
поправлены, а другие нет.

---

## Требование к правке

Дать `.btn-submit` тот же минимум 44px на `pointer: coarse`, что уже есть у `.tab-btn`,
`.chr-modal-btn` и ещё два десятка классов в общем списке
([`styles.css:2913-2927`](../../web/public/styles.css#L2913-L2927)). Два варианта
реализации — решить на этапе техспеки:

- **A.** Добавить `.btn-submit` в существующий общий список (`.btn-icon, .tab-btn, ...`).
  Плюс: один список, вся точка правки в одном месте, нулевой риск конфликта специфичности
  с чем-то ещё. Минус: список и так длинный (24 селектора), становится ещё длиннее.
- **B.** Отдельное однострочное правило `@media (pointer: coarse) { .btn-submit { min-height: 44px; } }`
  рядом с базовым определением `.btn-submit` ([`styles.css:2628`](../../web/public/styles.css#L2628)),
  по образцу точечных блоков вроде `.cdet-lib-pick-btn`
  ([`styles.css:3672`](../../web/public/styles.css#L3672)). Плюс: правило физически рядом
  с классом, который меняет, легче найти при следующей правке `.btn-submit`. Минус: ещё
  один (25-й) `@media (pointer: coarse)` блок в файле, где уже есть один общий.

Проект уже использует оба паттерна (один большой общий список + россыпь мелких точечных)
примерно поровну — прецедента, однозначно диктующего выбор, нет. Рекомендация: **вариант
A** — раз подходящий общий список уже существует и `.chr-modal-btn` (сосед `.btn-submit`
по общему базовому CSS-блоку box-model, [`styles.css:2616-2617`](../../web/public/styles.css#L2616-L2617))
уже в нём — логично держать пару вместе.

### Проверка на побочные эффекты

`.btn-submit` используется и в тесных местах (например, ряд из нескольких кнопок в
`.btn-row`, ссылка на класс в `archive.js`/`log-session.js`) — при добавлении
`min-height: 44px` под `pointer: coarse` нужно визуально/замером проверить хотя бы
2-3 таких места на реальном узком экране, не только вкладку «Бэкап», где кнопка одна
в блоке. Существующий общий список это в принципе уже применяет к 24 другим классам без
известных проблем — переиспользование того же паттерна снижает риск, но проверка нужна
не только на вкладке-источнике находки.

## Вне объёма

- `.chr-modal-btn` — не трогать, уже соответствует (ложная тревога исходного QA-отчёта,
  задокументирована выше).
- `.btn-secondary` (модификатор поверх `.btn-submit`, напр. «Сохранить настройки») —
  наследует высоту от `.btn-submit` автоматически, отдельного правила не требует.

## Открытых вопросов нет

Единственная развилка (вариант A/B реализации) — с рекомендацией, не блокирует техспеку.
