## Задача

Реализовать новую под-вкладку «Титулы» внутри Библиотеки → Сородичи (третья,
рядом с уже существующими «Кланы» и «Секты»), строго по техспеке:

**`docs/design/2026-08-06-library-titles-techspec.md`** — прочитай её целиком
первой, это основной документ задачи. Она содержит все 10 разделов с точными
местами в коде (файл+строки) для каждой правки: формат markdown-карточки
титула, `web/lib/titles.js`, роуты в `web/routes/library.js`, разметка в
`web/public/index.html`, загрузка в `web/public/scripts/v20-sheet.js`, форма
создания/редактирования в `web/public/scripts/library-authoring.js` (включая
новый тип поля `checkbox` — «Негативный титул»), CSS-бейдж, тест-план и
раздел «Порядок выполнения» в конце.

## Контекст

Titles — новая категория библиотеки, архитектурно копирующая уже существующий
паттерн «Кланы» (K3) / «Секты» (K4): config-driven система через
`web/lib/<kind>.js` (парсер) + `web/routes/library.js` (CRUD с canon-protection
через строку `- **Авторское:** да`) + `index.html` (под-вкладка) +
`v20-sheet.js` (загрузка/рендер) + `library-authoring.js` (общая форма
создания). Титул отличается от Клана/Секты двумя вещами: полем
«Принадлежность» (свободный текст — не всегда секта, у части титулов это
клан или смертный род) и опциональным флагом «Негативный титул» (бейдж на
карточке), которого раньше в библиотеке не было.

**Файлы для чтения перед стартом:**
- `AGENT_BRIEF.md`
- `docs/design/2026-08-06-library-titles-techspec.md` — основной источник правды по задаче
- `web/lib/clans.js`, `web/lib/sects.js` — образец парсера, на который равняется `titles.js`
- `web/routes/library.js` (секции по Кланам/Сектам — CRUD, `_artFileSet`/`_withArt`)
- `web/public/index.html` (секция `data-tab="lib-kindred"`, `data-kin-group="clans"|"sects"`)
- `web/public/scripts/scripts.js` (делегат клика `data-kin-group`)
- `web/public/scripts/v20-sheet.js` (`loadKindred`, `ensureClans`/`ensureSects` и вся связка вокруг них)
- `web/public/scripts/library-authoring.js` (`_LIB_FIELD_DEFS`, `_LIB_FIELD_RECORD_KEY`, `_LIB_KIND_CONFIG`, `_libCollectForm`)
- `web/public/styles.css` (`.lib-card-sect`, `.lib-card-custom-badge` — образец для нового `.lib-card-negative-badge`)

## Ограничения

- НЕ трогать `web/.env`
- НЕ трогать `cities/*/archive/events.md` напрямую
- НЕ менять `system/schema/card_schema.md` — титулы вне контракта карточки персонажа
- НЕ менять `web/lib/parsers.js` (парсер персонажей/локаций) — это отдельный модуль,
  титулы используют свой собственный `web/lib/titles.js`
- НЕ добавлять npm-зависимости на клиентский JS
- Не выдумывать канонные факты WoD — если техспека или данные Аналитика
  чего-то не покрывают, оставь `// нужна сверка` и опиши это в отчёте
- Следуй технической спецификации буквально, включая точные названия
  файлов/функций/CSS-классов, если она их даёт — она уже согласована с
  архитектурой проекта; отходи от неё только если найдёшь явную ошибку/несостыковку
  с реальным кодом, и тогда явно опиши расхождение в отчёте

## Критерии готовности

- [ ] `web/lib/titles.js` создан, парсит формат карточки титула из техспеки §2/§3
- [ ] Роуты `GET/POST/PUT/DELETE /api/library/titles` работают, включая canon-protection и `hasArt`
- [ ] Под-вкладка «Титулы» видна в UI рядом с «Кланы»/«Секты», рендерит пустой список без ошибок на старте (в `system/library/titles/` пока нет записей)
- [ ] Форма создания титула работает, включая чекбокс «Негативный титул» и текстовое поле «Принадлежность»
- [ ] Бейдж «Негативный титул» отображается на карточке когда флаг установлен
- [ ] Линтер карточек без ошибок: `node system/schema/validate_cards.js` (титулы вне его области, но не должен ничего сломать)
- [ ] `npm test` в `web/` без новых падений (сверить с известными пред-существующими падениями e2e V20-листа)
- [ ] Сервер стартует без ошибок, `POST /api/restart` применяет правки
- [ ] Проверено вживую в браузере (скилл `run-sanguine-web`): создание 2-3 тестовых записей (например «Князь», «Изгой» с флагом «негативный»), редактирование, удаление — полный цикл
- [ ] Тестовые записи, созданные для проверки, удалены из `system/library/titles/` после теста
- [ ] `web/tests/report.html` не закоммичен как часть диффа (`git checkout -- web/tests/report.html` после `npm test`)

## Что НЕ входит в задачу

- Массовое наполнение данными — переписывание ~91 описания титулов «своими словами»
  из `docs/design/2026-08-06-library-titles-data.md` в реальные `.md`-карточки.
  Это отдельный последующий этап (техспека §9), явно вынесенный за рамки этой
  задачи. Создавай для тестирования только 2-3 записи, не более.
- Генерация арта (ComfyUI) для карточек титулов.
- Любые правки в `cities/*/`.
