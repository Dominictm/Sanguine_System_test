## Executive Summary

Нашёл **системный класс дефектов**: экранирование пользовательского ввода
против структурных символов формата хранения (перенос строки в
markdown-списке, символ `|` в pipe-таблице) отсутствует в трёх независимых
местах — «Отношения» персонажа, строки «Хронологии мира» и строки
«Состояния мира». Один из них (перенос строки в «Отношениях») даёт
**необратимую порчу файла карточки**, которую не может исправить ни один
существующий инструмент в приложении — это и есть главная находка отчёта.

Остальные функции раздела (переименование, ред. полей, дневники,
soft-delete, защита от path traversal, конкурентный edit по индексу
строки — 409 при устаревшем индексе) работают надёжно и без нареканий.

## Найденные дефекты

### 1. [ВЫСОКИЙ] Необратимая порча карточки через перенос строки в «Отношениях»

**Компонент:** `PUT /api/characters/:slug/relations` (`web/routes/characters.js:280`).

**Шаги:**
1. `PUT .../relations` с `lines: ["Злодей — Враг\n- **Слаг:** hacked"]`
   (строка с embedded `\n`).

**Ожидаемый результат:** сервер либо отклоняет строку с переносом (`400`),
либо схлопывает перенос в пробел — как это уже делает соседний эндпоинт
`PUT .../fields` (`.replace(/\n+/g, ' ')`, строка 254 того же файла).

**Фактический результат:** перенос сохраняется буквально. Кусок после `\n`
(`- **Слаг:** hacked`) попадает в файл КАК ОТДЕЛЬНАЯ строка вне
отступа блока «Отношения» — то есть перестаёт быть частью списка отношений
и застревает прямо в теле карточки:
```
- **Отношения:**
  - —
- **Слаг:** hacked
```
**Подтверждено:** это не «пока не почищено» — я специально проверил после
последующего «очистить все отношения» (`lines: []`) — осиротевшая строка
`- **Слаг:** hacked` **осталась на месте**. Регулярка, которая ищет блок
«Отношения:» (`web/routes/characters.js:296`, `relRe`), матчит только
корректно отступленные `  - ...` строки и останавливается на первой
«чужой» строке — значит orphan-строка невидима для всех последующих
правок через API/UI и требует ручной правки файла вне приложения.

**Причина:** `PUT .../relations` не нормализует `\n` в значениях `lines[]`
(`.trim()` убирает только начальные/конечные пробелы, не внутренние
переносы) — в отличие от `PUT .../fields`, где такая нормализация есть.

**Кто может воспроизвести из UI:** поля «Имя»/«Вид отношений» в вкладке
«Отношения» — обычные `<input>` (не `<textarea>`), Enter в них новую строку
не создаёт — прямым набором с клавиатуры не воспроизвести. Реалистичный
путь — вставка (paste) многострочного текста в поле (поведение browser-specific,
не проверялось отдельно) либо прямой вызов API.

**Рекомендация:** `.replace(/\n+/g, ' ')` на каждый элемент `lines[]`,
как уже сделано в `fields`.

### 2. [ВЫСОКИЙ] Тот же класс дефекта — символ `|` рвёт pipe-таблицы «Хронологии мира» и «Состояния мира»

**Компоненты:** `web/lib/parsers/timeline.js` (`_serializeTable`,
строки 33-37) и независимая копия того же кода в
`web/lib/parsers/worldState.js` — обе просто джойнят ячейки через `' | '`
без экранирования `|` внутри значения.

**Шаги (Хронология мира):**
1. `POST /api/timeline/epoch/<эпоха>/row` с `event: "Битва | резня в порту"`.

**Фактический результат** (файл + структурированное чтение):
```
| 2021 | Тест | Битва | резня в порту |  |
```
— строка молча расползается на лишнюю колонку: `event` становится
`"Битва"`, а `"резня в порту"` **тихо съезжает в поле `source`**
(«Источник»). Ни ошибки, ни предупреждения.

**Тот же тест на «Состоянии мира»** (`POST /api/world-state/section/<секция>/row`,
`cells: ["Камарилья | Анархи", "Напряжение"]` в 2-колоночную секцию) даёт
идентичный результат: 2 переданные ячейки превращаются в 3
(`["Камарилья", "Анархи", "Напряжение"]`) — то же самое съезжание колонок,
подтверждает, что это не единичный баг, а системная проблема в обоих
независимых копипастах `_serializeTable`.

**Почему это вероятнее, чем кажется:** `|` — обычный символ, которым люди
часто заменяют тире/паузу в неформальном тексте («Битва | резня») — не
нужен злой умысел, чтобы получить молчаливо съехавшие данные.

**Рекомендация:** либо экранировать `|` → `\|` при сериализации ячейки
(и разэкранировать при парсинге), либо просто заменять `|` на похожий
символ (например `∣` или `/`) на входе с уведомлением пользователя.
Одинаковый фикс нужен в обоих файлах (`timeline.js` и `worldState.js`) —
имеет смысл вынести `_serializeTable`/`_parsePipeTable` в общий модуль
заодно, раз уж правится.

### 3. [СРЕДНИЙ] Нет защиты от дублирующегося заголовка эпохи в «Хронологии мира»

**Шаги:** `POST /api/timeline/epoch` дважды с одинаковым `heading`.

**Фактический результат:** создаются ДВЕ секции `## Эпоха QA` в
`timeline.md`. Все последующие операции (`addTimelineRow`,
`updateTimelineRow`, `removeTimelineRow`, `removeTimelineEpoch` — все в
`web/lib/parsers/timeline.js`) ищут секцию через `blocks.findIndex(b =>
b.heading === heading)` — то есть **всегда** попадают в первую по счёту
секцию. Вторая (дубликат) становится недостижимой через API: в нею нельзя
добавить строку, её нельзя отдельно удалить (удаление по имени уберёт
только первую), она просто зависает в файле мёртвым грузом.

**Рекомендация:** `addTimelineEpoch` — проверять `heading` на
уникальность перед добавлением, `409`/`400` при дубликате (аналогично уже
существующей защите от дубликата персонажа в `POST /api/characters`).

## Non-functional / полезные наблюдения (не баги)

- **Русское словоформление счётчика событий**: заголовок вкладки
  «📋 События сессий» рендерит `${evCount} событий` без склонения — при
  одном событии страница буквально озаглавлена **«1 СОБЫТИЙ»**
  (`web/public/scripts/archive.js:205`). Мелочь, но заметная: это первое,
  что видит Рассказчик на странице. Рекомендация: функция склонения по
  числу (1 → событие, 2-4 → события, 0/5+ → событий, с исключением
  11-14 → событий).

## Что проверено и работает корректно

- **Переименование персонажа** (`PUT /fields`, поле `name`) — H1 меняется
  корректно; переименование в пустую строку — тихо игнорируется (без
  ошибки, но и без последствий — не баг, просто отсутствие явного
  фидбэка «имя не изменено»).
- **Правка произвольных полей карточки** — точечная замена конкретной
  строки-буллета, без побочных эффектов на другие поля.
- **Неизвестный ключ в `fields`** — тихо пропускается, не ломает карточку.
- **`fields`/`relations`/`delete-preview`/`delete` на несуществующем
  слаге** — везде корректный `404`.
- **Мягкое удаление персонажа** — архивация в `_deleted/`, вычищение
  строки из `characters_index.md`, де-линковка структурных ссылок в
  других файлах, повторное удаление того же слага — `404` (не падает).
- **Удаление изображения** — защита от path traversal в имени файла
  (`/[/\\]|^\./` тест) действительно блокирует `../`-паттерны, `400`.
- **Дневники** — валидация периода (`ГГГГ-ММ` или `retrospective`),
  пустой текст отклоняется, `append` корректно накапливает записи в одном
  файле, `replace` полностью перезаписывает, путь к файлу (`?file=`)
  защищён от traversal (`403` подтверждён живьём на `../../../server.js`).
- **Конкурентное редактирование строк «Хронологии мира»/«Состояния
  мира»** — `PUT`/`DELETE` строки по индексу возвращают `409 "Данные
  изменились, обновите страницу"`, если индекс вне диапазона (то есть
  таблица успела измениться) — хорошая защита от гонки двух вкладок.
- **Валидация обязательных полей** при создании эпохи/строки/секции —
  везде понятные `400` при пустом заголовке/тексте события/колонках.
- **`/api/chronicle`** агрегирует события из всех модулей хроники
  корректно (участники, локация, последствия, ссылки на модуль/финал).
